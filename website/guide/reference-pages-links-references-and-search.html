Reference/Pages, links, references, and search

  • Pages, links, references, and search
    • The precise rules behind the moving parts: pages and aliases, links and tags, block references and embeds, the two reference panels on every page, and every search surface from the switcher to the saved-search page. Workflows/Find and revisit walks through using them in order; Feature showcase shows each construct rendered.
  • Pages and namespaces
    • With a Chinese IME, type 【【 for [[]] or （（ for (()): the caret lands inside the ASCII reference and the usual page or block search becomes active. Conversion waits until composition finishes, so it does not interrupt choosing a character. Typing 【 or （ around selected text wraps it with ASCII brackets or parentheses; a second opener makes a reference. At the start of a line, 《〈 becomes < and opens the block command menu.
    • A page is any name you link to. Type [[ while editing and completion offers existing pages and their aliases; an alias row is labelled alias of its page, so you can tell it from an ordinary page with a similar name. Whether Enter prefers the strongest existing match or exactly what you typed is Settings → Editor → Advanced → Link autocomplete default (OG adaptive, Prefer existing, Prefer exactly what I typed), and an exact existing name always selects the existing page.
    • A page link whose page does not exist yet renders in a dimmed link color with a dotted underline, still readable and still clearly a link. It still works — opening it lets you create the page. Tags are never dimmed, because most tags in a normal graph have no page of their own. Tine marks the difference on purpose; Logseq only dims untitled pages.
    • A link to the web or to a file is underlined with a solid line, as in Logseq; a link to a page has no underline, and a block reference is underlined in the link color. Each kind has its own CSS class, and the underline and the missing-page color are --tine-* tokens, so your custom.css can restyle them: see Workflows/Customize Tine's look.
    • A page with an icon:: property (an emoji, such as icon:: 🏁) shows it on its title, in links to it, and in front of its name in the sidebar's Favorites, Recent and All pages lists and in the right sidebar. A favorite without an icon keeps the star. The icon:: property stays visible in the page-properties block; click its row to edit it.
    • To set an icon without knowing the property syntax, open Page actions (the ⋯ beside the title), then Set page icon… below Page properties…. Enter an emoji or short text such as AB, then press Enter or Save icon. On Windows, Win + . opens the native emoji picker; on macOS, use Control + Command + Space. Remove page icon clears it. Icons in the sidebar lists follow edits immediately, including external file changes. Markdown stores icon::; Org stores #+icon: through the same page-property editor.
    • Page names ignore letter case: [[foo]] and [[Foo]] open one page. On a case-insensitive disk that page opens under the spelling its file already has, so a differently cased link never creates a second page.
    • A link to a page that does not exist yet is not broken — opening it gives you an empty page, and its file is written only when you first type something into it.
    • A name with slashes, like Project/Roadmap, is a namespace: it nests under Project in the sidebar's collapsible namespace tree, and a namespaced page gains an automatic Hierarchy section listing its descendant pages.
    • Journals are pages too — one per day, reachable from Journals in the sidebar. Their formats, templates, tasks, and agenda are mapped in Reference/Journals, tasks, and scheduling.
    • The application chrome — toolbar, sidebars, buttons — is not text-selectable, so a stray drag never starts a selection there; page content and editors stay selectable.
  • Links and tags
    • [[Page]] links and #tag tags run on the same machinery: a tag links and collects references like any page, and a tag with no page of its own is perfectly normal. A page's tags:: property values render as navigable links too.
    • A labelled page link such as read the welcome shows your words while opening the page. External [label](https://…) links are ordinary Markdown, bare URLs and emails autolink, and Mod+L inserts a link around the selection. http, https and mailto links open in your browser or mail app. A file: link — [Test](file:///home/you/report.odt), or [Test](file://D:\test.txt) on Windows — opens that file or folder in whatever application your system uses for it, on desktop; a file that is no longer there is reported instead of doing nothing. A file path is read from the graph folder, from any page or journal: [report](files/report.pdf) opens files/report.pdf inside the graph, while [report](../files/report.pdf) opens a file in the sibling files folder outside the graph. Parent steps such as ../../ are preserved. Absolute paths such as /home/you/report.pdf and D:\notes\report.pdf also open through the same desktop file opener as file: links. These links look ordinary and show the resolved path on hover. Use [spaced](<../files/my file.txt>) for spaces. Links into the graph's assets folder keep Logseq's established graph asset route. Opening local files is available on desktop only, including for file: URLs; Android and iOS report the refusal. Tine does not rewrite links when you move files or graphs. A link to another app, such as zotero://…, obsidian://… or shortcuts://… on iOS, first asks whether to open it, showing the whole link, and then opens it in that app. javascript: and data: links never open.
    • Click a link to follow it. Shift+click opens it in the right sidebar, Ctrl/Cmd+click opens it in the other pane, and middle-click opens it in a background tab. While editing, Ctrl+O opens the link at the caret and Ctrl+Shift+O opens it in the right sidebar — matching Logseq's shortcuts, no mouse needed.
  • Aliases
    • Put alias:: Another name, Third name among the page properties at the top of a page — as Feature showcase does with alias:: Kitchen sink (features) — and links under those names land on the same page.
    • The page then shows aka chips for every name it answers to ("Also known as — other names that link here"); click one to edit the header. The raw alias:: property stays out of the under-title property list.
  • Page and block properties
    • Rendered block properties use a separate row for each key; click the key to open its page. The earliest property group supplies the display, with the last value for a repeated key. Later groups remain in the file even when they are not displayed.
    • Properties are the key:: value lines at the top of a page and under a block's first line, and every one of them is editable from a form — not only by typing raw lines. Click Page actions beside a page's title (or right-click the title) and choose Page properties…, or type /page properties while editing; right-click a block for Properties…. The form lists the properties that page or block really has.
    • A page's form always offers Aliases, Tags, Display title, Icon and Public, even when the page has none of them yet. Every other property the page carries follows, each under its own key and each removable outright. Add a property takes any key you like.
    • Machine-managed properties stay out of the form: id:: and collapsed:: are never listed, and the tine. keys behind Sheets and saved searches are edited from those surfaces instead.
    • Each property is written in the form its own file uses. A Markdown page gets key:: value; an Org page gets a #+key: value file directive, and an Org block its :PROPERTIES: drawer — the shapes Logseq itself reads back.
    • A key does not have to be plain ASCII. klíč:: hodnota is an ordinary property: it can be added, changed, and removed again like any other.
    • A read-only page — a bundled Guide page — offers no property editing at all, rather than a form whose writes would be dropped.
  • Block references and embeds
    • Page and block menus keep reference, embed and link copying under Copy as ▸. Open that submenu to choose the form you need.
    • Settings → Editor → Click a block reference to zoom in makes a plain reference click zoom into its source block, including on another page.
    • Fold a page embed with the host bullet's arrow or the ordinary Collapse/Expand keyboard commands. Only its page-name line remains; expanding restores its content. The choice is saved on the host block, never the embedded page. If the host has children, the same fold hides those too. This works in the main pane and right sidebar.
    • Hover a page link or block reference for a read-only preview. An alias shows its source page's title and page properties. Click the title to open that page in a new tab, a block bullet to open that block in a new tab, or Open source to open the preview's source. These actions switch to the new tab. The preview stays open while its … → Page actions menu is open. Editing requires opening the source.
    • A context menu's Open in new tab keeps your current tab active and confirms Opened in a new tab. Phones and tablets have no tab strip, so their menus omit Open in new tab and offer Open in sidebar; Ctrl/Cmd-click and middle-click there open the link in place.
    • Settings → Appearance → Advanced → Fine-tuning → Block embed breadcrumbs optionally shows the source page and parent trail above a block embed. It starts off and is saved on this device.
    • A block embed has a subtle shaded background in both light and dark themes, so you can distinguish the embedded occurrence from an ordinary block.
    • Type (( while editing: the popup searches blocks, and choosing one inserts a durable ((reference)). Tine first writes a stable id:: on the source block, so the reference survives renames, reloads, and restarts.
    • The reference renders as a link-styled copy of the source text and stays in sync: edit the source and every reference updates. A referenced task keeps its marker and checkbox; tick the checkbox inside the reference to complete or reopen the source task. A per-block reference-count badge reveals the referencing blocks.
    • Deleting referenced blocks or merging them with Backspace/Delete shows a notice about references that broke or now point to the surviving block, with Undo to restore the blocks and their ids.
    • Click a reference to go to the block; Shift+click opens it in the right sidebar and Ctrl/Cmd+click in the other pane. Right-click an inline reference for Open in sidebar, Go to block, Copy block ref, and Copy block embed; with nothing selected, Mod+C copies a reference to the block you're editing and Mod+Shift+C copies an embed.
    • {{embed [[Page]]}} and {{embed ((id))}} inline a whole page or a block with its context. A page embed's bullet row carries the page's name as a link (with a page glyph), and the page's blocks sit one indent step below it, on the same outline grid as ordinary children, under an accent-colored guide. Embeds are live editing surfaces: edit inside an embed and the source changes. A block embed follows its source's fold state live; folding the embedded block inside one embed is remembered by that embed alone (as a collapsed:: property on the block holding the {{embed}}), never on the source or on another embed of it. When a block contains only a block embed, drag its visible root bullet to move the embed on the host page; clicking that bullet still zooms into the source block. Move block up/down on an embed's top block moves the source block among its own siblings, as in Logseq; since the embed looks the same afterwards, a short notice says which page it moved in, with Show to open it there. The same notice appears when a move from Linked References or a query result takes the block out of what that panel shows.
  • The reference panels on every page
    • Pages tagged with "X" appears on page X before Linked References when other pages include X in their page-level tags:: property. It lists the tagged pages as links and can be folded. Inline block tags still belong to Linked References.
    • Linked References sits at the bottom of the page (and of a page opened in the right sidebar): every block that links here, grouped by source page, with a count in its header. It's live — edit in place. A page that links here from its page properties (such as tags::) is listed as its properties row; click the row to fix a property name or value right there, as you would on that page. The funnel button opens a filter: a Search reference text box, a Clear button, an "N of M references" count, and page/tag chips, listed alphabetically with their counts, that cycle include → exclude → off (hover a chip for the reminder).
    • A page and its aliases share one chip labelled with the page's canonical name. Its count is the number of reference blocks using that page or any alias; a block using two aliases counts once. Include or exclude applies to every alias. As in Logseq, a reference must carry every included chip and none of the excluded ones. Linked References saves these choices in the page's Logseq-compatible filters:: property; an older filter naming an alias selects the same canonical chip. Unlinked References shares the alias chips but keeps its choices on this device.
    • One bulk button folds every group at once: it shows Expand all if any group is folded, otherwise Collapse all. Each group has its own disclosure. The block reference-count panel uses the same toggle.
    • A page with a lot of backlinks opens its Linked References folded, so the outline stays reachable. Logseq's :ref/linked-references-collapsed-threshold in config.edn sets where "a lot" starts (Logseq's default is 100); set it to 0 if you would rather every page start folded and open the panel yourself.
    • Unlinked References, folded by default: plain-text mentions of the page title that were never linked — the fastest way to find where a name was written without brackets. Each mention is highlighted inside its excerpt, and the highlight is clickable: it opens the source page with that exact mention selected, ready to link or edit. Show full block / Show excerpt toggles the whole block and marks every mention; a block whose mentions do not all fit the excerpt also gets a numbered jump row. The block's bullet opens the source block (Shift+click: right sidebar, Ctrl/Cmd+click: new tab, Alt+click: other pane).
    • Both panels have their own Copy / export action. The currently visible entries start selected; uncheck any you do not need, then export the selected blocks grouped by source page as Text, OPML, or HTML. Linked References exports its filtered set, and ordinary page export remains separate.
    • Hover previews show surrounding context without leaving the page.
  • Finding things
    • Ctrl+K, the quick switcher, searches page titles plus the visible text of blocks. Sections are Pages, Create, Commands, Blocks and — inside a page — Current page; with an empty query it lists recent pages. Enter opens the highlighted result; Shift+Enter opens it in the right sidebar; Ctrl/Cmd+Enter opens it in a background tab and keeps the switcher open; Alt+Enter opens it in another pane; middle-click opens a background tab. Load more results… appears when more are available.
    • Ctrl+Shift+K searches only the open page's blocks. Mod+F searches all open main and split panes and expanded right-sidebar items, in pane order then sidebar stack order. The in-page find bar offers next (Enter) / previous (Shift+Enter) and a "1 / N" count; folded branches are expanded before the match is highlighted, and the match itself is scrolled into view even inside a block taller than the window.
    • Find and replace. The arrow at the left of the find bar opens a Replace with row. Replace (or Enter in that field) changes the highlighted match and moves to the next; Replace all (or Ctrl/Cmd+Enter) changes every match on the page you opened Find in — not the right sidebar, query results or other pages — as one Undo step. Matching ignores case and accents exactly as Find does. It edits the text you see, as typing would: a link's address and hidden properties such as id:: are never changed, and a match Tine cannot tie to editable text (inside a link's markup, say) is left alone and counted in the message. On a phone, open Find from the page's ⋯ menu → Find in page.
    • The five Search syntax forms, listed in the switcher footer: foo bar (both terms), foo OR bar (either), foo -draft (exclude), "exact phrase", and /[A-Z]{3}/ (case-sensitive regular expression).
    • Title matches rank exact, then prefix, then substring, then fuzzy, with block text after them. After you deliberately open the same result more than once for a query, it may break ties among equally strong matches; that history stays on this device, and Settings → Editor → Advanced → Learn Ctrl+K choices disables it, with Reset ranking to clear it.
    • Search ignores accent marks and compatibility-width differences as well as case, so cafe finds café, lodz finds Łódź and Tine finds Ｔｉｎｅ. Set :feature/enable-search-remove-accents? false in config.edn to turn that off. Marks that make a different letter still count: か does not find が, и does not find й, and क does not find कु; елка finds ёлка. Page identity stays narrower: those spellings may still be separate pages.
    • Search scans your loaded graph text directly, so results are always current with your own edits; while it works the switcher says Searching…, an empty answer says No matched results, and More matches exist — narrow your query to see them. means the list was cut short.
    • To find Chinese page titles or aliases without changing your input method, enable Settings → Editor → Advanced → Match Chinese page names by Pinyin. In Ctrl+K or [[ completion, beijing, bei jing or bj finds 北京. Native name matches always come first; block text is not transliterated. This device preference defaults on for a Chinese UI or system language, otherwise off; Reset Pinyin matching to language default restores that default. Turning it off refreshes open Ctrl+K results immediately.
    • Mandarin matching uses one default dictionary reading per character, so polyphonic names may need that reading (重慶 uses zhongqing). Traditional characters also work. Japanese kanji receive Mandarin readings (東京 matches dongjing, not tokyo). Names sharing Pinyin remain separate results in a stable order.
  • Search tabs and saved searches
    • From the search box, press ArrowDown to highlight the first result. ArrowUp / ArrowDown move through page and block results and scroll the highlighted row into view. Enter opens it in a new tab; Shift+Enter opens the right sidebar, Ctrl/Cmd+Enter opens a background tab, and Alt+Enter opens another pane. ArrowUp on the first result returns to the search box, so you can keep typing; the list does not wrap around at either end.
    • Open search tab in the switcher footer turns the current search into a graph-scoped search tab titled "Search: …" with its own search box. The tab survives restarts and writes nothing to your graph until you name it. Clicking a result opens a new tab and keeps Search unchanged. Middle-click or Ctrl/Cmd-click opens a background tab; Shift-click opens the right sidebar and Alt-click opens another pane. Page results offer the same right-click menu as the switcher.
    • Search / List / Table / Board are presentations of one result membership: switching the view never changes which blocks matched. Filters / Advanced narrows by friendly fields — all words, any words, an exact phrase, excluded words, a regular expression — and Edit as visual query opens the row-by-row builder; Explain query shows what Tine understood. Choosing blocks and choosing a presentation are separate steps — see Workflows/Structure repeated information for that split in action.
    • A text search returns pages and blocks, shown as two sections in that order, each with its own count and its own display control (Display pages for the pages, Display for the blocks). An empty section says No matching pages. or No matching blocks. rather than hiding.
    • Pages match takes three values: Names and aliases (the default — exact, prefix, substring, fuzzy and regular-expression matching, not exact equality only), Block content (a page counts when one of its own blocks matches the same search), and Names or content (the union). It changes page membership only; the Blocks section evaluates the same block search either way. The choice is saved as tine.page-match-scope.
    • The Display panel offers View, Group by, Sort, Columns, Summarize (count, sum, average) and Sample, then Done.
    • Naming a search tab — typing into "Name this search to save it as a page" and pressing Save page — creates one ordinary page whose only block is a {{query}} plus the tine.view::, tine.page-match-scope:: and tine.page-* / tine.block-* display lines the two sections were using. From then on it behaves like any page: linkable, searchable, always fresh. A page that already exists with the chosen name or alias is never overwritten — you pick another name ("Choose another title"). The saved block is a single result list with one Display control; the two-section Pages / Blocks layout belongs to the search tab.
    • A {{query [[Page]]}} block uses Logseq's path-refs rule: a block matches when it mentions the page, when a bullet it lives under does, or when it sits on that page — so the page's own outline always appears. The backlinks-only answer to the same question is the page's Linked References panel.
    • A query that asks about pages rather than blocks — (page-property …), (page-tags …), (namespace …) — lists the pages themselves.
    • {{query (all-page-tags)}} lists every page that some page uses as a tag.
    • A query's text is edited at the foot of its sheet, in TQL — SQLite expression syntax over a fixed vocabulary of block and page fields, prop('key'), page references and the any/every/off forms. The compact reference is Workflows/Find and revisit → Query text (TQL). A word Tine cannot read is named, and the query returns no results rather than a shorter answer.
    • When a query finds nothing, why empty? under the result asks which condition emptied it: for each condition, how many blocks it matches on its own and how many the query would match without it. That is usually enough to see which one to loosen.
