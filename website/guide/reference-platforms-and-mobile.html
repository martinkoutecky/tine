Reference/Platforms and mobile

  • Platforms and mobile
    • "Does this work on my phone?" hides two different questions: what changes because a window is narrow, and what changes because Tine is running as the Android app instead of a desktop one. This page keeps them apart and maps what current releases ship on each side.
  • Question 1 — is the window narrow?
    • Below a 640 px window width — on any device, including a desktop window you shrank yourself — the left and right sidebars stop squeezing the page and become drawers over it. Dismiss one by tapping the shaded outside edge, using its close control, pressing Esc, or pressing Android Back.
    • At 640 px and wider — including tablets — both sidebars are persistent panes that can stay open together and keep their resize controls.
    • The boundary is width, nothing else: it follows the window, not the device, so the same desktop shows both faces as you resize it.
  • Question 2 — which app is running?
    • Some behavior keys off Tine detecting a native mobile platform, whatever the window width. On a phone-sized screen (shorter edge under 700 px) the Android app hides the tab strip and disables split panes, so one page keeps the phone screen. Tablets have room for two documents and keep split panes.
    • The desktop apps (Linux, macOS, Windows) keep the full window model — tabs, pinned tabs, split panes, saved workspaces, and multiple windows — toured in Workflows/Keep context visible.
    • In both cases your graph is the same ordinary Markdown/Org files, so these are interface and surface differences, never different content formats.
  • On Android
    • Sidebar, Search, Back and Forward are in the top bar, in the same place whether or not you are editing, as on the desktop apps. On a very narrow phone (about 320 px wide) Back and Forward fold into the ⋯ menu. To have them within thumb reach, turn on Settings → Appearance → Navigation buttons at the bottom (off by default, this device only): the four buttons then sit in a row at the bottom of the screen, which gives way to the editing toolbar while the keyboard is up. When you close the keyboard with Back or the keyboard's hide key, the row comes back at once, although the block stays in editing; tap the block to bring the keyboard and the editing toolbar back. The same setting exists on iOS. The editing actions stay in their separate horizontal toolbar above the keyboard; there are no vertical toolbar pages.
    • Your graph is a real folder on the device's own storage. On first run you grant "All files access" and pick the graph folder (a Syncthing folder works), and Tine reads and writes that folder directly — coexisting with the Logseq mobile app on one graph. Cloud document providers such as Nextcloud can't be opened directly: use your provider's sync-to-local-folder feature, then pick that local folder in Open graph. The file watcher polls there by default (Settings → Files → Watch for external edits), so external edits appear shortly after they land.
    • An editing toolbar docks above the on-screen keyboard with the actions a keyboard lacks: Outdent / Indent, Move block up / down, Soft newline, TODO, Camera, Voice memo, Undo / Redo, Date picker, [[ ]] and (( )), the Slash menu, and a hide-keyboard button. Undo uses an arrow bending left; Redo uses an arrow bending right.
    • Camera and Voice memo capture a photo or an .m4a recording straight into the graph's assets/ folder and insert the link at the caret — permission-prompted on first use. One that finishes after you switch graphs is saved into the graph it was started in and not inserted; Tine names the graph and the file.
    • Share to Tine from any app. Pick Tine in Android's share sheet to send text, a link, or one or more images. The item becomes a new block at the bottom of today's journal, the same place quick capture files to, and Tine shows Captured to today's journal. Shared images are copied into the graph's assets/ folder. If Tine can't add the item yet, for example because no graph is open or saving fails, it keeps the item and tries again the next time you open or return to Tine. Retrying never loses the item. It can add it twice in one rare case: Tine closed or crashed just after the journal was saved and before it noted the item as done. Reopening an old share from the recent-apps list after Tine was closed or the phone restarted can also add it again. Sharing the same thing twice adds it twice. Tine saves a share whole or not at all: if it can't take every part, for example more than 32 images, a file over 64 MiB, a file that isn't an image, or a file from Tine itself, it says so and saves nothing.
    • Launcher shortcuts and a Quick Settings tile. Long-press Tine's launcher icon for Today, Quick capture and Search. Add the Quick capture tile from the Quick Settings editor. Quick capture opens today's journal with an empty block at the bottom, ready for typing.
    • Hardware Back navigates within Tine — dismissing a dialog or drawer first and stepping back through page history, exiting to the system only at the root.
    • PDFs use that same one-pane history. Open a PDF link in place, press Notes to visit its highlights page, and use Hardware Back to return first to the PDF and then to the source page. Desktop-style PDF tabs and companion splits stay off on a phone.
    • Plugins and themes follow the same lifecycle as desktop — install (always disabled at first), review capabilities, enable, settings, disable, uninstall — and a package that did not declare Android shows Unavailable on it. The hands-on path is Workflows/Extend Tine.
    • The whole interface scales through Interface size (saved per device) and the native status/navigation icons follow your selected theme.
  • Touch gestures on a phone
    • Swipe a block to restructure it. Swipe a block right to indent it, left a short way to outdent it, and left a longer way to select it and open its action menu. A revealed arrow shows indent or outdent before you let go; it switches to a circled more icon when the swipe will open actions. An unavailable indent or outdent has no arrow. The left-swipe outdent band is 40–139 px; actions start at 140 px, giving you more room to outdent. Short or mostly-vertical movements are ordinary scrolling and do nothing. Swiping is off while you are typing in the block, inside tables, code blocks, queries, drawings and media, and with more than one finger, so it never fights text selection or panning.
    • Swipe in from the left edge to open the left drawer; a swipe that starts elsewhere, or that is mostly vertical, does not.
    • Back is one ladder everywhere. It dismisses an open dialog, menu or image first, then closes an open drawer, then steps back through page history. On Android the hardware or system Back gesture climbs that ladder and exits only at the root. Where Tine takes Back from the screen edge instead (iOS), the same left-edge swipe goes Back when there is something to go back to, following your finger and snapping back if you let go early; otherwise it opens the drawer.
    • The image viewer takes touch. Pinch to zoom, double-tap to zoom in and out, drag a zoomed image to pan it (keep dragging past its edge to reach the next image), swipe sideways to move between the page's images, and drag up or down to close. A single tap shows or hides the buttons instead of closing; use the × button, drag the image up or down, or press Back to close.
    • Turn the block swipe off for chosen pages. To stop swipes from acting inside blocks that reference particular pages (a kanban board, say), list their names in config.edn: :mobile {:gestures/disabled-in-block-with-tags ["kanban" "board"]}. A block that references a listed page, and everything nested under it, ignores the swipe. This is the same setting Logseq uses.
  • What stays different on Android
    • The always-on-top capture window is desktop-only. The tine --capture desktop shortcut and its window over other apps have no phone counterpart. On a phone, capture with the share sheet, the Quick capture shortcut or tile, or iOS Shortcuts and Siri, described above and under iOS below. The desktop setup lives on Features/Quick capture.
    • One route at a time on a phone — pages and PDF readers share one history, with no tab strip, split panes, or second windows; the desktop multi-window model does not exist here.
    • Long-press a page reference or tag to preview its page without navigating away. Choose the … button in the preview header for Page actions, the same menu offered by a desktop right-click. Tap outside the preview to dismiss it; a quick tap still follows the link. Other links keep their long-press context menu, and holding ordinary text keeps the system's text selection and selection toolbar.
    • Export to PDF is desktop-only — printing is unavailable inside a mobile WebView, so the page menu does not offer it here.
    • Updates come through your install channel. The in-app update checker and installer are off on mobile: a sideloaded release-signed APK is replaced by taking each new APK from the GitHub releases page, an F-Droid install updates through F-Droid, and a Google Play install updates through Google Play. The F-Droid build omits the network plugin/theme catalogue and keeps local sideloading.
  • On desktop (Linux, macOS, Windows)
    • Everything the phone skips is here: tabs with pin, reorder, and reopen, split panes, saved workspaces, multiple windows, the modifier-click gestures, and global quick capture. Releases cover Linux and Windows on x64 and ARM64, and macOS as one universal app.
    • In-app updates run on Windows, Linux and macOS — the app checks once per launch and Settings → About → Check for updates offers Install update, which downloads, verifies and installs in place after saving your changes. Windows and Linux relaunch immediately; macOS offers Restart after installation, saving any further changes before restarting. Releases ship signed macOS updater archives for Intel and Apple Silicon from the signed and notarized universal application. If the updater cannot fetch, verify or install an update, Tine opens the releases page so you can download and replace the app manually. If a failed macOS installation cannot restore the previous app, look beside the original app or in your home folder for Tine (previous version).app (or Tine Beta (previous version).app). If neither folder is writable, the updater keeps its temporary backup. The updater shows the saved location when it reports one; open that bundle to recover or download and replace the app manually.
      • Installed from the Microsoft Store (MSIX)? Then the Store keeps Tine up to date: Settings → About says "Updates come from the Microsoft Store.", and Tine's own update checker and installer stay off on that install.
      • Running the portable ZIP (Windows)? Tine keeps its settings, sessions, backups, plugins and WebView2 data in the tine-data folder beside Tine.exe, never in AppData, and it updates by download: quit Tine and extract the new ZIP into the same folder, keeping tine-data. A first portable launch starts with fresh settings; to bring the settings of an installed Tine along, quit Tine and copy %APPDATA%\<app id> to tine-data\<app id>\roaming and %LOCALAPPDATA%\<app id> to tine-data\<app id>\local (<app id> is page.tine.Tine, or page.tine.TineBeta for Tine Beta). Your notes stay in your graph folder.
      • Automatic checks are ON by default. In Settings → About, turn off Check for updates automatically to stop startup checks and update notifications on this device. You can still use Check for updates manually; turning automatic checks off does not change how package-manager or manual-download installs receive updates.
    • Install as a Flatpak (Linux, Beta). Each Beta release also carries a Flatpak bundle for 64-bit Intel/AMD, named like Tine-Beta_<version>_x86_64.flatpak, among the other downloads on the Beta release page. Install the downloaded file with flatpak install --user Tine-Beta_<version>_x86_64.flatpak, then start it from your app menu (flatpak list shows its application id for flatpak run). It installs next to a stable Tine Flatpak and keeps its own settings, and it can read and write graph folders inside your home folder only: a graph on another disk or under /mnt or /media is out of its reach, unlike the other Linux builds. Updates are manual: the in-app updater does not apply to it (it offers a download link instead of installing), so download the new bundle from the release page and run the same command again.
    • System tray (optional). In Settings → Appearance, turn on Show Tine in the system tray to get a tray, notification-area or menu-bar icon. Its menu has Open Tine, Quick Capture and Quit; clicking the icon shows and focuses the main window, or hides it when it is already in front. Two more switches appear once the icon is on: Minimize to tray makes minimizing the main window hide it (instead of leaving it in the taskbar) until you open it from the tray, and Start minimized to tray launches Tine with the main window hidden (your graph still loads, so it is ready the moment you open it). All three are off by default and apply to this device only. Closing the main window still quits Tine, and other windows are never hidden by the tray. If your desktop has no tray (some Linux desktops need an AppIndicator or StatusNotifier extension), Tine says so under the switch, shows its window as usual, and ignores the two minimize options until a tray exists. If the tray disappears while Tine is running (the panel that hosted it quits), Tine shows its window again and turns the two minimize options off until you re-apply the setting. A start-minimized launch at login waits a few seconds for a late tray before it gives up and shows the window. The tray needs the system's libayatana-appindicator3 library; the .deb and .rpm recommend it, the Flatpak bundle carries its own, and the AppImage uses the one on your system. Starting Tine again shows the main window if the tray had hidden it, and opening a graph or link always shows it.
    • Any folder on your disk can be a graph — choose it with the ordinary folder picker; there is no sandboxed document picker.
    • On macOS, Tine draws its window with the system's web engine — the same one Safari uses — and needs the engine of Safari 15.4 or later, which means macOS 12.3 (Monterey) or later. Apps get the engine that came with macOS: updating the Safari app on an older Mac leaves the one Tine uses unchanged, so the app bundle declares 12.3 as its minimum system version. If the web engine is too old, Tine explains this at startup instead of opening half-working. Opening PDFs needs Safari 17.4 or later; the rest of Tine does not.
  • iOS today
    • A public beta is on TestFlight: install Apple's TestFlight app, then open that link. An App Store install updates through the App Store.
    • Graphs live in the app's own folders. Open or create a graph inside On My iPhone → TineOutline or iCloud Drive → TineOutline; Tine refuses folders from other Files providers for now and says so. Creating a graph asks for its name after you choose the parent folder, and creates a child folder with that name. An iCloud graph is downloaded to the device before it opens, and a remembered graph reopens after an app update.
    • The iPhone and iPad app uses the same mobile interface as Android, so the notes above about one route at a time, bullet context menus and desktop-only features apply there too.
    • Share to Tine. Pick Tine in the share sheet to send text, a web page, a link, or up to five images. The sheet confirms Saved to Tine. The next time you open Tine, the item becomes a block at the bottom of today's journal, exactly as on Android.
    • Spotlight finds your pages. Pages of the graph open in Tine show up in iPhone search by title, with a short excerpt, and tapping one opens it in Tine. Hidden pages are never added. Only the current graph is indexed, and switching graphs replaces the index.
    • Shortcuts, Siri and the Home Screen. The Shortcuts app and Siri offer Add to Tine journal (it saves without opening Tine, and the block appears the next time you open it), Search Tine and Open page. Long-press the app icon for Today's journal, Quick capture and Search.
    • Plugins do not run on iOS yet. Themes work; downloadable WebAssembly plugins stay off until Tine has the extra review surface Apple requires for them.
  • Shaping a shared item
    • When an Android share brings Tine forward, Tine opens the journal where it saved the item and reveals the shared block, like following a block reference. With several shares, it reveals the last item in the batch. The Captured to today's journal notice stays. Retries leave your current page open, as do iOS shares and App Intents saved without opening Tine. In-app quick capture keeps the page you are editing open.
    • Shared items follow Logseq's mobile rules for each platform. On Android a link becomes a titled link, YouTube and similar video links become {{video …}}, posts on X or Twitter become {{twitter …}}, and text highlighted in a browser goes before its link. On iOS the shared text is kept as it is and the link follows it unchanged, as Logseq's iOS share does. Images follow as asset links, one per line.
    • The block uses Logseq's :quick-capture-templates from config.edn. The default text template is **{time}** [[quick capture]]: {text} {url}, and on Android :media sets the template for a single shared image. {time} is when you shared the item, and {date} is the date of the journal it is added to.
    • The same destinations open from tine://today, tine://capture, tine://search?q=… and tine://page/<name> (a page of the open graph). Each one only opens something in Tine and never writes to your graph.
