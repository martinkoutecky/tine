- # Tips & shortcuts
	- A quick tour of the things that aren't obvious on day one. (Shortcuts are remappable in Settings.)
	- On Linux and Windows, **Ctrl+Q** runs **Quit Tine**, closing every graph window after saving pending edits. You can remap or disable `app/quit` in **Settings → Keyboard shortcuts**. On macOS use the app menu's **Cmd+Q**. If a page cannot be saved, the usual close warning keeps it available for recovery.
	- In **Settings → Shortcuts**, use **Add keybinding** to keep a command's default and add another key. Click a binding to replace it, or remove one binding while keeping the others. Every alternative runs the same command; conflicts with other commands are shown beside it. Changes are saved on this device. In a graph's `config.edn`, OG-compatible alternatives use a vector, for example `:shortcuts {:go/search ["mod+k" "mod+shift+k"]}`.
	- On desktop, the formatting toolbar follows your selection, even near the bottom of a long block. It appears below the selection when there is no room above; choose an action there to format the selected words.
	- With a non-Latin keyboard layout, shortcuts and recording use the physical key's Latin letter or digit: **Ctrl+K** still works when that key types **л**. Latin layouts such as AZERTY and Dvorak keep their letter-based shortcuts. Text you type keeps the selected language.
- ## Find anything — Ctrl+K
	- To switch graphs, press **g Shift+G**, choose a remembered graph with **Up/Down**, then press **Enter**. **All graphs** is also in the command palette.
	- While editing a block beside an embedded YouTube video, press **Ctrl/Cmd+Shift+Y** to insert its current playback time, just like **/Embed Youtube timestamp**. The inserted `{{youtube-timestamp N}}` macro becomes a clickable time: click it to seek the matching or last played video. Without a ready player, the shortcut inserts nothing. What you should see: the video jumps to the inserted time when you click it.
	- **Ctrl+K** opens the quick switcher: jump to a page, search the text of any block, or run a command — all from one box. **Ctrl+Shift+P** opens the command palette (commands only).
	- **Search page names** searches only page names and aliases; **Search block content** searches only block text. Both commands start unbound: assign keys in **Settings → Shortcuts**, or run them from the command palette.
	- Use **Ctrl+Shift+K** to search only the focused page, including children hidden under folded bullets. In the ordinary Ctrl+K switcher, press **Shift+Enter** on a page or block to send it to the right sidebar without leaving your current page.
	- Use **Search syntax** for phrases, alternatives, exclusions, and regular expressions. Choose **Open search tab** to keep the complete search in a graph-specific tab instead of choosing only one hit. To open a blank search tab directly in the focused pane, assign a key to **Open search tab** (`go/search-tab`) in **Settings → Shortcuts**; it is unbound by default.
	- The result tab separates **Pages** and **Blocks**. Pages match names and aliases by default; choose **Pages match → Block content** to find pages containing a matching block, or **Names or content** for both. Blocks still show the matching text. The choice stays with the tab and a saved search uses `tine.page-match-scope:: content` or `both` on its query block.
	- Each section has its own **Display** control: show Pages as a table with columns from authored page properties while Blocks stay a list, for example. Name the search and choose **Save page** to keep both choices on an ordinary query page. The compact filter button handles friendly fields and date ranges; **Query builder** opens the deeper visual editor when needed.
	- Page-title matching keeps exact, prefix, substring, and fuzzy results in that order. Repeated choices may break ties inside one class using device-local history; disable or reset this under Search settings if you prefer fixed ordering.
	- **Ctrl+F** searches the main and split panes and expanded right-sidebar items in that order; **Enter** / **Shift+Enter** move forward / backward through matches. The arrow at the left of the find bar adds **Replace** and **Replace all** for the page you opened Find in.
	- In a Search tab, clicking a result opens a new tab and keeps the search available (**Settings → Editor → Advanced → Search results open in → This tab** opens it in the same tab instead); right-click a page result for the switcher's page actions.
	- In the quick switcher or a Search tab, **Ctrl/Cmd-click** a result to open it in a background tab, **Shift-click** for the right sidebar, or **Alt-click** for another pane.
	- The quick switcher, page search, suggestions, and find-in-page ignore accents, case, and compatibility-width differences by default: `cafe` finds `café`, `lodz` finds `Łódź`, and `Tine` finds `Ｔｉｎｅ`. Marks that form another letter stay significant (`か` and `が` differ). To require accents in these searches, set `:feature/enable-search-remove-accents? false` in `logseq/config.edn`. This changes matching only; page names and Markdown keep their original spelling.
- ## Follow a link without the mouse — Ctrl+O
	- With the caret inside a `[[link]]` or a `#tag`, **Ctrl+O** opens that page and **Ctrl+Shift+O** opens it in the right sidebar. This works while you are editing, so you can follow a name you just typed without reaching for the mouse.
- ## Select whole blocks — Ctrl+A
	- While editing, **Shift+click** another block's text to select the whole range as blocks and leave the editor. The first and last blocks are included in full; cutting or moving the range also takes their children. Shift-click again to adjust the range from the same starting block.
	- While editing, **Ctrl+A** first selects the block's text; press it again to select the block with its children, and keep pressing to widen the selection to each parent and finally the whole page. **Shift+Up** onto a parent always takes all of that parent's children with it.
	- **Edit selected block** returns one selected block to editing. It starts unbound; assign a key in **Settings → Shortcuts**. You can bind it to **Escape** if you prefer that way back into editing; without that binding, Escape keeps its ordinary selection steps.
- ## Copy a link to a block — Ctrl+C
	- With several blocks selected, right-click any selected bullet: **Copy blocks**, **Cut blocks**, and **Delete blocks** act on the selection; **Copy block refs**, **Copy block embeds**, and **Copy link** sit in the same menu and act on the same selection. Cut and delete take one Undo step; cutting keeps the complete subtrees for pasting. Right-clicking an unselected bullet acts on that bullet.
	- While editing with no text selected, **Ctrl/Cmd+C** copies a reference `((id))` to the block and **Ctrl/Cmd+Shift+C** copies an embed `{{embed ((id))}}`. With text selected, both keep their ordinary copy meaning.
- ## Comment on a passage — Ctrl+R
	- **Resolving.** Click **Resolve** to close a whole thread. It leaves the margin, its passage highlight and open counts. The page's **N resolved** control reveals closed threads greyed in place; **Reopen** brings one back. In narrow panes and on phones, revealing adds a separate **N resolved** entry beside the source block; it opens the closed threads in the live popover or bottom sheet, with dates and Reopen. Closed threads never regain highlights or markers until reopened. Replying to a resolved thread reopens it. Undo restores the previous state. Only the root stores `tine.resolved:: true`; resolving never marks a task DONE.
	- **Comment dates.** New comments and replies store `tine.date:: 2026-11-07T13:37Z` once, in UTC to the minute. The quiet header date uses your interface language and local time. Editing never updates it; messages keep file order. Older comments without a date show none. Ordinary blocks get no stored date. In Markdown, each date adds 30 bytes plus indentation per message; Resolve adds 21 bytes plus indentation on the root, each through the existing whole-file save.
	- **Message outlines and folding.** In a dated thread, each dated block is a message; undated children are its editable bullet outline, with ordinary nesting and references. Older undated threads stay flat and are never rewritten. **Collapse** folds a message's body or a whole thread to **N replies**; **Expand** restores it. The block menu, also opened from a comment's author handle, offers **Collapse all comments on this block** in one undo. Folds use Logseq's `collapsed:: true`, so they travel with your graph.
	- While editing a block, select a few words and press **Ctrl/Cmd+R**. Tine adds a comment under that block that quotes the words and puts the caret in it. Other routes do the same: the selection toolbar's **Comment** button (the speech bubble at the right edge, also on touch screens), **Comment on selection** in the command palette, and **Comment on selection** after right-clicking words you have selected in a block's text. In Settings → Keyboard shortcuts the shortcut is listed as **Comment on selected text**. With nothing selected, the comment is about the whole block.
	- A comment is an ordinary child bullet carrying a `tine.quote::` property (with `tine.quote-prefix::` and `tine.quote-suffix::`, a few words on either side, so the comment stays on those words if they appear again later). Context grows until the occurrence is unique; an empty context property marks the start or end of the block. The page stays plain Markdown and opens in other apps as nested bullets. New replies are direct children of the thread root. A bullet with a `tine.author::` property, such as one an assistant or script wrote, shows that name in a small chip.
	- A comment shows as a tinted card with the quoted words above it, and those words are marked in the block. If the block is later edited so the quoted words are gone, the card keeps the quote struck through with **quoted text changed**; the comment is never dropped. If several occurrences match equally, the card says **quoted text ambiguous** rather than marking an arbitrary occurrence. On a touch screen, select words in rendered text and tap **Comment** in the formatting toolbar; entering edit mode first is unnecessary.
	- **Replying.** Hover or focus a thread and click its **Reply…** box at the bottom. **Enter** and **Shift+Enter** insert a line break; **Ctrl/Cmd+Enter** or the visible **Send** button submits. **Escape** or **Cancel** discards the draft. An abandoned empty reply creates no block and does not save the page. While editing an existing comment or reply, Enter and Shift+Enter also add lines; Ctrl/Cmd+Enter or Escape finishes editing without creating another block. These keys work in both the classic and CodeMirror editors. Selecting words inside a thread and choosing **Comment** or pressing **Ctrl/Cmd+R** adds a reply with a short quote inside that same thread.
	- **Deleting.** The **×** button at the top right deletes that comment and its replies; **Ctrl/Cmd+Z** restores them together. Comment and reply editors hide every `tine.*` property on all platforms, including iPad and iPhone; the original property bytes stay in the file when you save the edited words.
	- **Author marks.** `tine.author::` means who wrote this block's words; it does not inherit from a parent. On ordinary blocks it stays hidden while editing, and the author mark and chip stay visible. The line is centred in the bullet-to-text gap without moving the text. Consecutive sibling blocks with the same author share one continuous line, with a chip only on the first block; author changes, child outlines, embeds and comment threads break runs. Hover or focus an individual mark to see that block's author. Click the chip and choose **Remove author** to remove the attribution. **Remove author** is also a command: run it from **Commands** (Ctrl/Cmd+Shift+P) with the block selected, or assign it a key under **Settings → Shortcuts** (it ships without one) and press it while editing the block. Editing keeps the original author property bytes, including on a blockquote. An ordinary `author::` property, for example a book's author, remains editable.
	- **Show/Hide author marks** in the command palette controls the gutter lines independently of **Show/Hide comments**. Both switches are together under **Settings > Appearance**. Marks are shown by default. Names stay available when the lines are hidden. Bind the command under **Settings > Keyboard shortcuts** if you want a shortcut; it has no default key. These display choices never change the graph's author properties.
	- **Your name.** Type a name under **Settings > Editor > Your name** and the comments and replies you write are saved with `tine.author:: <your name>`, so a graph you share with other people shows who wrote what. You still read **you** on your own screen. While the name is empty nothing is written. The name is stored on this device and used in every graph, not stored in the graph. In a graph that is under git, the first comment or reply you write without a name asks **How should your comments be signed?** once: **Use this name** saves it, **Skip** writes the comment without it and Tine does not ask again (the setting stays available). If two people share a graph without setting their names, both see each other's unsigned comments as **you**.
	- **Where comments appear.** On a wide pane, a page with comments moves its text left and shows threads in a column on the right, ordered by where their quoted words appear. The journal feed uses the same width rule, with each day's page owning its margin column; split panes also use their own available width. Each thread starts beside its passage when space permits; a focused thread stays there while neighboring cards move away without overlapping. A block shows no count of its own comments. Click a comment to edit it there. Hovering a comment marks its words, and hovering marked words picks out their comment. In narrower panes nothing sits beside the text: hover the highlighted words to open their thread in a live popover, where you can edit and reply, just like a page link's hover preview. The popover stays open while you type in it, and a click on the words still places the caret. On a touch tablet, tap the highlighted words instead. A thread whose quoted words changed or match in more than one place has nothing to highlight, so its block shows a small comment marker that opens it. On phones, tap a highlight or the block's comment chip to open a bottom sheet, with the text visible above; swipe between passages or use the previous/next buttons. Threads on the same passage stay grouped. These width rules apply to pages, journals, split panes, sidebar and embeds. Own threads stay reachable even when the block is collapsed; inline cards are never an automatic fallback. Every response reads at one level in file order, even if another editor nested replies more deeply; viewing them never rewrites that nesting. Right-click the name chip (long-press on a phone) for the block menu, where **Zoom into block** lives.
	- **Same passage and hidden descendants.** Threads about the same resolved passage share one card and one quote, with separate reply boxes and actions. Commenting on that passage again focuses the last thread's reply box without creating anything; choose **New thread** to start another independent discussion. A collapsed body block with open threads on hidden descendants shows an outlined **N below** chip. It counts open threads, never replies or the block's own threads. Tap it to expand the block.
	- **Editing body text.** Comments and all their replies are annotations in Tine's editor. **Backspace**, **Delete** and the arrow keys skip whole threads when moving between body blocks. **Enter** at the end of a block whose only children are comments creates a sibling; ordinary children still make Enter create a first child. **Tab** and **Shift+Tab** cannot move a comment or nest a body block inside a thread. Comments cannot be dragged, and body blocks cannot be dropped or pasted inside their threads. Moving or deleting the commented body block takes its comments with it. The file still contains ordinary child bullets, readable in Logseq and other editors.
	- **Display choice.** In **Settings > Appearance > Comments**, choose **In the margin** (the default) to follow pane width, or **In a popup** to keep comments out of the way until you hover their highlighted words. **In a popup** works the same at every width, including Wide mode; phones still use the bottom sheet. The choice applies immediately to pages, journals, splits, sidebars and embeds, and unsent reply drafts survive switching. It is saved on this device and changes nothing in the graph. Show/Hide comments takes precedence over either choice.
	- **Review comments.** Run **Next comment** or **Previous comment** from the command palette to review the current page in margin order. Each step scrolls the passage into view and focuses its live thread, opening a popover or phone sheet when needed. Their previous/next buttons step across the page too. Resolved threads join the review only while **N resolved** reveals them. Steps stop at either end, and reveal collapsed ancestors using the normal saved expansion. In the journal feed, review stays on the day you last used (the first visible day until you choose one). Both commands have no default key; bind them in **Settings > Keyboard shortcuts**.
	- **Hiding the comments.** Open the page actions menu (the visible **…** control, also on mobile) and choose **Hide comments** or **Show comments**. You can also press **t** then **m**, run **Show/Hide comments** from the command palette, or switch off **Show/Hide comments** in Settings > Appearance, next to Wide mode and Document mode. While they are hidden a page shows no comment anywhere (no column, no cards, no marked words, no counts or N below chips) and the arrow keys skip them; the comments stay in your file and nothing is deleted. Send or discard an unsent reply before hiding comments. Writing a new comment, or opening a link or search result that leads to one, shows them again. The choice is kept on this device. In Settings > Keyboard shortcuts you can give **Show/Hide comments** a shortcut of your own.
- ## Insert a block above
	- To put a bullet *above* an existing one, press **Enter** with the caret at its very start. Some bullets keep Enter for themselves — inside a code block it adds a line of code — so for those, right-click the bullet's dot and choose **Insert block above**. That works on any bullet, including the first one on a page.
- ## New block after the children, and merging selected blocks
	- **Alt+Enter** while editing adds an empty block at the same level as the block you are in, after its whole subtree, and puts the caret there. On a block whose children are showing, plain **Enter** at the end puts the new block first among them; Alt+Enter puts it after the last one, before the next sibling. The block you pressed it in is not split. It is the command **New block after this block's children**, so you can rebind it under **Settings → Shortcuts**. In a sheet cell Alt+Enter keeps adding a child.
	- **Merge selected blocks** is in **Commands** (Ctrl/Cmd+Shift+P) and starts unbound; assign a key under **Settings → Shortcuts**. With two or more blocks selected on one page, it joins their texts, one line each, into the first selected block, in the order you see them, and keeps every child under it. A selected block's own children that are not selected keep their sub-bullets. It is one Undo step. As with **Backspace**, a block ID that other blocks refer to moves to the merged block when it has none; if that would lose a referenced ID, nothing changes and Tine says why. Selections with a query, an embed, a sheet or a PDF highlight, or blocks from two pages, are refused.
- ## Paste plain text, or paste as a link
	- To keep pasted video URLs as plain links, turn off **Settings → Editor → Auto-embed pasted video links**. It is on by default and covers YouTube, Vimeo, Loom and Bilibili in both editors, including Quick Capture. Tine never fetches video titles on paste. What you should see with it off: pasting a YouTube URL keeps the URL instead of inserting a `{{video …}}` embed.
	- **Ctrl/Cmd+Shift+V** pastes the clipboard as plain text inside the current block: copied web headings, bold runs and lists are not converted, and multiline text stays in one block instead of becoming several. On macOS, **Option+Shift+Cmd+V** and **Edit → Paste and Match Style** do the same thing. Ordinary **Ctrl/Cmd+V** keeps converting copied web content and outlines.
	- **Paste as link** turns what you copied into a link without typing the syntax. Copy a URL or a block reference, select some words in a block you are editing, and run it: `see context` becomes `[context](https://…)` or `[context](((id)))`. With nothing selected the link is inserted bare. It ships without a key, so assign one under **Settings → Shortcuts** (the command palette lists it too, but opening the palette leaves the editor, so use the key). Ordinary paste over a selection is unchanged.
- ## Block commands you can bind
	- These commands ship without a key, so nothing you already use changes. Assign keys under **Settings → Shortcuts**; each acts on the selected blocks, or on the block you are editing when nothing is selected.
	- **Duplicate block below (with children)** puts a copy, children included, right under the block, and the caret follows it, so pressing it again stacks copies. The copy gets its own ids; one Undo removes it.
	- **Duplicate block above (with children)** does the same above the original. The caret follows the new copy, so repeated presses stack copies upwards. It also ships without a key; bind it under **Settings → Shortcuts**.
	- **Insert child block** adds an empty last child under the block and starts editing it, which works where **Enter** then **Tab** cannot, such as an embedded block with no children yet. A folded block opens so the new child shows.
	- **Collapse (one level)** folds the immediate children of the block, and folds the block itself once its children are all folded (or have no children of their own). **Expand (one level)** works the other way: a folded block opens by itself first, with its children still folded; each further press opens the next level with folded children, ignoring leaves, until everything is expanded, and each press is one Undo step. With nothing selected they start at the page's top-level blocks.
	- **Set depth 0** to **Set depth 9** show a block down to an exact level in one step, from any state of its tree. Depth 2 opens the block and its children and folds the grandchildren; depth 1 opens the block and folds its children; depth 0 folds the block. Only the levels the command makes visible change: blocks deeper than that are hidden anyway and are left as they are, expanded or folded. With several blocks selected each one is set from its own level, and blocks already in the right state are not touched. Each press is one Undo step. They are in **Commands** (Ctrl/Cmd+Shift+P) and start unbound; assign keys under **Settings → Keyboard shortcuts**.
	- **Copy block refs of the selected blocks** copies a `((id))` reference for each selected block, one per line in the order you see them, the same text as **Copy block refs** in the block context menu.
	- **Search for the selected text** opens search with the selection already typed in. The ready-made key for it, **Ctrl/Cmd+Shift+F**, is Logseq's *toggle favorite*, so it is left for you to choose.
- ## Create one yourself
	- 1. Press **Ctrl+K**.
	- 2. Type part of a page name, a block phrase, or a command such as `Open Guide`.
	- 3. Press **Enter** on the highlighted result.
	- 4. What you should see: Tine jumps to the page/block or runs the command without leaving your graph.
- ## Slash commands — /
	- Type **/** at the start of a bullet for a menu: tasks, headings, a code block, a `/calc` live calculator (hover a result to copy it), dates (Scheduled / Deadline), callouts, queries, a math block, asset upload, and more. `/Code block` opens a language picker; typing a language after an opening backtick or tilde fence offers the same completion. Inside a fenced code block no menu opens, neither `/` nor `[[`, `#`, `((`, `<` or a property's `::`, in either editor, so code is typed as it is (Logseq opens them there too); inline code between single backticks still offers them.
	- Planning dates and source selections use Logseq's leading-whitespace rules, including leading BOM and NEL characters: BOM is whitespace; NEL remains content.
	- On a journal page, **/That day** inserts a link to that journal's date, even when it is an older day. **/Today** inserts today's date. Both use your graph's journal title format.
	- With Simplified Chinese selected, each built-in slash row shows its English keyword followed by a Chinese gloss in parentheses. English typing still finds the same commands; Chinese glosses are searchable too: type `/表` to find **Table (表格)**. The `<` section picker also searches its Chinese labels, such as `<引用` for Quote. Selecting a row inserts the original syntax.
- ## Journal days
	- A day named only by links or tags is a journal even before it has a file. All Pages lists it once when **Show journals** is on, and page queries include it. Your configured journal title and filename formats refer to the same day.
	- **g j** opens the Journals feed. **g h** opens the graph's home page, chosen in **Settings → Graph** or set as `:default-home {:page "Page name"}` in `logseq/config.edn`; Tine also opens it when it opens a graph without a saved session. With a saved session, Tine restores every tab's last page, order and pin state, and the same active tab. Renaming the home page (or a namespace it lives in) keeps it the home page; merging it into another page does not. With no home page set, or when that page no longer exists, **g h** opens the Journals feed. With `:feature/enable-journals? false` in `logseq/config.edn` and a home page that exists, the sidebar shows that page in place of **Journals** (as Logseq does); **g j** still opens the feed. **g n** and **g p** move to the next or previous calendar day from the journal you are viewing. From another page, they start at today.
	- A configured default journal template is inserted once for each new day, including when Tine stays open through local midnight. Choose a journal display date format in Settings; the three dotted day-month-year patterns are available there too. The display format does not rename journal files.
	- Opening a graph never renames journal files. If some are named by title instead of by date, their days look empty; **Settings → Backups & recovery** lists them under **Journal files named by title** with a **Rename to date names** button, which takes a snapshot first.
	- Hover a journal title row or focus one of its controls with the keyboard to reveal the carry buttons, in the feed and on a journal page. On touch devices without hover they stay visible. The buttons under today's journal pull unfinished tasks from earlier days. After midnight, yesterday's button changes to **Carry unfinished tasks → today**.
- ## Tabs
	- **Middle-click** any bullet, page, or search result to open it in a background tab. **Double-click** a tab to pin it, **drag** to reorder, **Ctrl+W** to close. Your tabs come back next launch. In a split view, a pane's only tab still has a close button (it closes the pane) unless it shows the journals.
	- Bind **Activate tab 1** through **Activate tab 8**, or **Activate last tab**, in **Settings → Shortcuts** to jump within the focused pane's tab order. They start unbound because **Ctrl/Cmd+1–9** already focus panes. A numbered slot with no tab does nothing.
	- Numbered tab/pane commands and sidebar/pane resize commands stay bindable in **Settings → Shortcuts** and are omitted from the command palette. **Carry unfinished tasks: last N days** uses the day count in Settings → Journals.
	- **Page links, block references, an outline bullet's dot, backlink headers, the sidebar and query results all take the same modified clicks**: **Shift-click** opens the right sidebar, **Ctrl/Cmd-click** or **middle-click** opens a background tab, and **Alt-click** opens the other pane (splitting one off if you have only one).
	- When a pane has more tabs than fit, use its tab-overview button to see every full title, activate or pin a tab, close it, or reorder it with the drag handle / **Alt+Up/Down** without guessing from truncated labels.
	- Use the command palette to **Toggle maximize active pane** and use the pane-size commands to grow or shrink the active pane with the keyboard. Run **Reset interface zoom** to return to normal scale.
- ## The sidebars
	- Assign keys in **Settings → Shortcuts** to **Grow left sidebar width** (`sidebar/grow-width`), **Shrink left sidebar width** (`sidebar/shrink-width`), **Grow right sidebar width** (`right-sidebar/grow-width`), and **Shrink right sidebar width** (`right-sidebar/shrink-width`). All four start unbound. Each press changes the width by 48 px within the same limits as dragging, and the width is remembered on this device.
	- Hover over a truncated page title in the left sidebar to see its full title. Titles that fit show no tooltip.
	- Below a page, **Linked References** and **Unlinked References** show where it is mentioned, including plain mentions in code and math. Use the copy button at the right edge of either header to select visible results and open the shared Copy / export dialog; an Org source stays Org in source export. An expanded section stays open when the page view remounts. A page with many backlinks opens Linked References folded; Logseq's `:ref/linked-references-collapsed-threshold` in `config.edn` sets where that starts (default 100), and `0` starts every page folded. In Linked References, a reference must match every included chip and none of the excluded chips; typed text narrows both results and available chips. The block-reference locations panel can collapse or expand all source groups.
	- **t l** toggles the left sidebar — journals, favorites, recents, all pages, and a namespace tree. Favorites and Recent can be folded independently. Choose **+ New group** to arrange favorites under plain-text labels, then drag a row up or down to reorder it, right to nest it under the row above (to any depth), or left to lift it out; deleting a group keeps what it held one level up. Tine keeps that arrangement on an ordinary editable page called **Favorites** (marked `tine.favorites:: true`) and still writes `config.edn :favorites` as the flat list Logseq reads.
	- Right-click a graph in the left sidebar to copy its folder path, show it in your file manager, open another window, or remove it from the recent graph list.
	- **t r** toggles the right sidebar; **Shift-click** any bullet's dot to open it there and keep it beside your work. Each right-sidebar item can be folded independently, and its menu can collapse, expand, or close them all. Drag an item by its header to reorder the list.
	- On a phone-width window (below 640 px), either sidebar opens over the page. Tap the shaded outside edge, use the close button, press **Esc**, or press Android **Back** to return to the page. Wider tablet and desktop windows keep the ordinary persistent, resizable sidebars.
	- Click the vertical outline guide below a bullet to expand its complete descendant subtree when anything inside is folded, or collapse all of those descendants when everything is open. The bullet itself keeps its ordinary one-level action.
	- Press **t o** outside a text editor to toggle all blocks on the current page: any folded branch expands everything; otherwise everything folds. In **Commands**, choose **Expand all blocks on current page** or **Collapse all blocks on current page** for an explicit direction. Right-click a bullet for **Expand all** or **Collapse all** in that block's subtree. A bulk fold is one Undo step and persists through the normal page save.
	- Mouse side buttons navigate **Back / Forward** through the current pane's history on desktop, including macOS. On macOS, **Cmd+[** and **Cmd+]** also work; **Alt+Left** and **Alt+Right** remain available. A side-button drag keeps its selection or drag action instead of navigating.
	- **Zoom in on block** and **Zoom out one level** are in **Commands** (Ctrl/Cmd+Shift+P) and start unbound; assign keys under **Settings → Keyboard shortcuts**. Zoom in acts on the selected block, or the block you are editing, and keeps your caret in it. Zoom out steps from a zoomed block to its parent, then to the page, and does nothing on the page itself, so you can press it repeatedly. Each acts on the pane you are working in and joins its Back / Forward history.
	- **Ctrl/Cmd+R** and **F5** no longer reload the app, so a stray press while using other shortcuts does nothing. While editing, Ctrl/Cmd+R is **Comment on selected text**, which you can rebind or clear in **Settings → Keyboard shortcuts**. To reload on purpose, run **Reload window** from **Commands** or give it a key there.
- ## Focus mode & dimming — t f / t b
	- **t f** (focus mode) hides the sidebars and toolbar so the screen is just your text; layered **Esc** steps back out.
	- **t b** (dim inactive blocks) fades everything except the bullet you're editing — a typewriter-style spotlight. Use it on its own, or let focus mode turn it on for you.
- ## Sync copies and merge conflicts
	- When Syncthing or Dropbox leaves a conflict copy of a page, or a git or Fossil merge leaves `<<<<<<<` merge markers in a file, an **N conflicts** badge appears at the bottom of the left sidebar. It opens the **Conflicts** page, which lists every page that needs a decision; **Discard copy** moves a sync copy to the graph trash (recoverable). The list comes from your files, not from a list Tine keeps in your graph: to avoid re-reading every page at launch, Tine remembers which pages it has already seen without merge markers in its own disposable launch cache, and reads any page it has not seen from the file.
	- Open a listed page to resolve it there, block by block: keep one side, the other, or both. Where the merge markers carry the common ancestor, Tine pre-selects the side that actually changed; nothing is applied until you choose **Apply resolution**.
	- Tine refuses to save a page that still contains merge markers, because rewriting it would re-indent the markers and silently lose one side. **Apply resolution** is the one save that may replace such a file; the file as it was first goes to the graph trash. A merged sync copy goes to the trash too.
- ## A few more worth knowing
	- Use the **…** beside an ordinary page title for its complete actions menu: open the source file, copy/export, inspect properties, rename, carry tasks, or delete. It is the same menu as right-click and works from the keyboard and touch.
	- In **Copy / Export**, choose **Plain text** for the text as displayed, without markup markers, or **Markdown** (**Org** on an Org page) to keep the original syntax: bold, highlighting, links, and properties.
	- Right-click a block and choose **Open in new tab** to keep that block in its own tab (on a narrow window the tab is listed under **Open tabs** in the left sidebar).
	- In **Settings → Shortcuts**, search by command or key and choose **Unbind** to remove a shortcut; the command stays available from places such as the command palette, and **Reset** restores its default instead. **Settings → Appearance** offers Light, Dark, and System themes. The Settings window can be maximized; it remembers that choice on this device.
	- **Settings → Help & diagnostics** creates a privacy-safe diagnostic report of this run and the previous one to attach to a bug report: operation names, outcomes, timings, counts, platform and build, never page content, titles, file paths or queries. If Tine did not close cleanly last time, it says so when it starts. Review the report and choose **Copy report**, or on desktop **Save report…**; nothing is uploaded, and the recorder keeps at most 1 MiB in Tine's own app data, never in your graph. The same tab also offers **Rescan graph** and **Verify synchronized graph**.
	- Renaming a page to the name of another existing page offers to **merge** them, as Logseq does: the blocks move to the end of the page that remains, the aliases join, links to the old name point to it, and the merged file goes to the graph trash (recoverable).
	- Renaming a page to a date, such as `2026-10-26`, when that day's journal exists offers to merge into the journal, whichever way the date is written.
	- Renaming a page to a name that is only another page's alias (`ML`, where **Machine Learning** has `alias:: ML`) asks three ways: **Merge into “Machine Learning”**, **Make “ML” its own page (still an alias of “Machine Learning”)**, or **Cancel**. A page of its own gets the file `ML.md`; **Machine Learning** keeps its alias, so links to `[[ML]]` still show in its Linked References. After the merge, queries that named the old page, such as `{{query (page "ML notes")}}`, name the page that remains (`Machine Learning`); links keep the name you typed (`[[ML]]`), and pages under the old name move under it (`ML notes/x` becomes `ML/x`).
	- A page cannot be renamed or merged onto a name inside its own namespace that is already used, such as `Foo` to `Foo/bar` when `Foo/bar` is a page or some page's alias: every page under `Foo` moves with it. Tine says so and changes nothing. A name inside it that is only linked is free to take.
	- A rename that only changes capitalization onto a file another page already uses (on a disk where names differ by case) is refused with that page's name; rename or merge that page first.
	- Tine saves pending edits before a rename. A page whose edits cannot be saved stops the rename only if the rename would change that page, or its unsaved text mentions the old name; the message names it. Other pages keep their unsaved edits through the rename. A page named by `title::`, or in Org by `#+TITLE:`, gets the new name in that line.
	- Change capitalization directly with **Rename**, for example `my note` → `My Note`. The filename, title and references follow together; two distinct files claiming that name still block the rename.
	- **Carry unfinished tasks** forward into today (from the command palette) — the last 7 / 30 / 365 days, optionally with their context.
	- **Export to PDF…** saves pending page edits before preparing the printout. If a page cannot be saved, Tine stops the export and shows an error so the PDF does not silently omit your changes.
	- Print and PDF exports keep the full path of images inside `assets/`, including subfolders and different images that share a filename.
	- Select several task bullets and press **Ctrl/Cmd+Enter** to advance each one through your workflow in a single Undo step. The selection toolbar can also wrap selected text as a page link or inline code.
	- **Undo is Ctrl/Cmd+Z and redo is Ctrl/Cmd+Shift+Z.** On Windows and Linux **Ctrl+Y** also redoes, because that is the key most editors there use; the shortcuts list shows it beside the binding. It is a second default rather than a second command, so remapping Redo replaces both.
	- **Code blocks**: type ``` (or choose **Code block** from the **/** menu) and Tine offers a language list; picking one fills in the opening fence and the closing fence for you. Clicking code opens a compact code view: only the code itself is in the text box, so Enter adds a line of code instead of splitting the bullet. This also works when prose and code share a bullet after **Shift+Enter**: clicking a code region edits only that region. To edit the language or add text before or after the code, in the classic editor enter the bullet from a neighboring bullet with **Backspace** or an arrow key: the whole bullet opens as source, including its fences. From code editing, **Escape**, moving out of the body with an arrow key, or **Backspace** at its start also reveals the source. These paths work on desktop and mobile. In a mixed bullet, you can edit the whole bullet as source; surrounding text stays intact. To delete the whole code block, right-click its bullet and choose **Delete block**; on desktop, right-clicking inside the code with no text selected opens the same menu. Backspace in an empty code block without child bullets removes the wrapper; if it is the last block, it becomes a normal empty bullet. Code blocks show line numbers and a display-only language label. Hover the card to **Copy code** without its fences. **Settings → Appearance → Wrap code lines** controls wrapping for all code blocks, in both reading and editing; it is off by default and remembered on this device.
	- **Drag a bullet onto another bullet and move a little to the right** (about 50 px into it) to make it that bullet's last child; nearer its left edge, the upper half places it before and the lower half after. A marker shows where it will land.
	- Typing `::` at the start of a line inside a bullet starts a property: the name goes to the left of the `::`, **Create** is offered first, and after a comma the value list leaves out values already on the line.
	- **Namespaces**: name a page `Project/Roadmap` and it nests under `Project` in the sidebar. This page lives under `Features`.
	- **Page names and files**: put `title:: Project/Roadmap` above the first bullet to give an existing page that name, even when its filename differs. Tine keeps the file at its existing path; links and page search use the title. Markdown and Org pages in other graph folders, such as `archive/`, are pages too. New pages get portable filenames, including names with punctuation.
	- **Hidden graph paths**: add `:hidden ["archive/private"]` to `logseq/config.edn` to exclude matching graph-relative path prefixes from pages and search. The files stay on disk. This also applies to pages outside the usual `pages/` and `journals/` folders.
	- **Page icons**: add a property like `tine.icon:: 📚` at the very top of a page (the ⌨️ on this page comes from Logseq's `icon::`, which Tine reads too). `tine.icon` stays visible in the page-properties block; Logseq's `icon`, `title` and `filters` stay hidden there. Use **Page properties…** to change them.
	- **Hidden metadata** follows Logseq: built-in lines such as `heading::`, `background-color::`, PDF highlight metadata and flashcard scheduling stay out of the text editor. Keys listed in `:block-hidden-properties` in `logseq/config.edn` also stay hidden in editors and rendered property lists. Editing or clearing the visible text keeps the original hidden property lines in the file, in Markdown and Org. Use **Properties…** to change or remove hidden values; heading and block colour also have their own block-menu controls. Ordinary `title`, `icon`, `filters`, `logseq.color` and `logseq.table.*` lines remain visible while editing.
	- **Page and block properties** are editable from a form, not only as raw `key:: value` lines: use **Page properties…** in the page menu (or `/page properties` while editing), or right-click a block for **Properties…**. The form lists every property the page or block really has; a page's form always offers Aliases, Tags, Display title, Icon and Public. Any other property can be changed or removed, and **Add a property** takes any key you like — it does not have to be plain ASCII. `id::`, `collapsed::` and `tine.` keys keep their own surfaces. Markdown writes `key:: value`, an Org page a `#+key: value` directive, and an Org block its `:PROPERTIES:` drawer. A read-only page offers no property editing at all.
	- Press **Escape** inside a code editor to edit the whole bullet as raw source, including the Markdown fences or Org source delimiters. This works in the classic and CodeMirror editors, including split panes and the right sidebar. The caret moves to the end, and source stays visible until you leave editing. Press **Escape** again to select the block.
	- **Toggle code block wrap** in the command palette switches the same device-wide preference as **Wrap code lines** and keeps your reading position, including in split panes and the right sidebar. Code cards above the visible reading row can grow or shrink without moving that row. This works with the classic and CodeMirror editors. It never changes note source. Assign your own binding in **Settings → Keyboard shortcuts**; there is no default shortcut.
	- **Interface zoom** with **Ctrl/Cmd + / - / 0** while the notes pane is focused. To return the whole interface to its default **100%**, open the command palette (**Ctrl/Cmd+Shift+P**) and choose **Reset interface zoom**. This leaves PDF/image zoom and block zoom unchanged; a focused PDF keeps its own **Ctrl/Cmd + / - / 0** controls.
