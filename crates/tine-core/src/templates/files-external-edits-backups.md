- # Files, external edits, and backups
	- **If closing warns about unsaved changes:** Tine tries to save everything before the window closes. If a conflict or a stuck save prevents it, a prompt titled “Quit without saving N pages?” says so and names each unsaved page. Choose **Go back** to stay (or **Discard and quit** to close anyway): a panel lists those pages with **Retry saving**, open, and **Copy draft**. A failed save's message stays up with **Review unsaved**, which opens the same panel. If a page cannot be saved when you switch graphs, Tine stays on the current graph with your edit and says so. For a conflict, look for the conflict banner or the **N conflicts** badge (below) and resolve it before you close. If a page still cannot be saved after you close Tine's last window, Tine does not quit over it: after half a minute it opens that graph again, and a message names each page whose edits are not on disk yet, and why (changed on disk, or saving fails).
	- **If Tine crashes or quits while a page cannot be saved,** that page's unsaved text is kept in Tine's app data (never in your graph). On the next start Tine puts it back on the page and saves it, and a message names those pages: “Recovered unsaved edits … — Tine is saving them”. If the file changed on disk in the meantime, the page shows the changed-on-disk banner instead (see [[Reference/Troubleshooting and recovery]]), so nothing is written over unseen. Text that saved normally is not kept there. Crash-recovery copies from an older Tine are left untouched as a backup; a message names their file once.
	- Your graph content stays in ordinary files shared with Logseq. Tine also keeps device settings and launch snapshots outside the graph. This page maps what is written where, and the safety nets around it.
- ## What lands on disk
	- **Pages and journals** — one Markdown or Org file per page. Existing files may live at the graph root or in nested folders; Tine saves each one back to its exact path. New files use the configured `pages/` and `journals/` folders.
	- **Assets** — pasted and uploaded files in `assets/`. Deleting a block never deletes its media.
	- **Copy image** on desktop offers the original asset file to your file manager without changing its bytes or imposing a file size limit. If an image is too large to preview, hover over **Preview unavailable** to use **Copy image**. This also works for `{{img ...}}` image macros. An already-open image viewer keeps copying the original file after an outside asset edit. Missing files keep their missing-image placeholder. Smaller images also offer a bitmap for chat apps and image editors; this compatibility copy keeps the 64 MiB encoded-data limit and decoded-memory limit, including PNG images. Paste files copied in Explorer, Finder, or a Linux file manager to import their original bytes unchanged. A screenshot or other pixel-only clipboard image is saved as PNG. Mobile and remote image copying keep their existing image clipboard behavior.
	- **Graph configuration** — `logseq/config.edn`, shared with Logseq: journal date formats, macros, and UI choices such as `:ui/show-brackets?` live there.
	- **Tine's view config** — harmless `tine.*` block properties on the view-owning block (see [[Features/Sheets]]). Everything else stays ordinary graph text.
- ## Saving
	- **If the graph folder moves, is replaced, or disconnects while open:** Tine stops graph writes and shows a sticky notice. Unsaved edits stay on this device. Close the window, then reopen the graph from its new location, or reconnect its drive and reopen it; Tine never recreates the old graph folder to save into it.
	- **A moved or unavailable graph:** a notice offers **Recover into this graph** and **Not now** when device recovery holds unsaved edits whose graph cannot be found. The graph may be moved or unavailable (for example, a disconnected drive); recover only if those edits belong in the current graph. Recovery is your choice: it saves this graph's pending edits first, then recovers through the ordinary save checks. If another window or host still holds those edits, recovery refuses: close that graph, wait for saving to finish, then try again. An outside change becomes a conflict for you to resolve. **Not now** leaves the edits on this device and the notice returns on the next open; it does not discard anything. On iOS, an app update that changes only the app-container location carries the device state over automatically when neither namespace is held by a host.
	- Keeping a graph open does not prevent ejecting its drive. After ejecting, saves fail and unsaved edits stay on this device; reconnect the drive and reopen the graph before continuing.
	- You never press Save: edits are written automatically to the same file the page came from, a moment after you pause.
	- Writes go through a guarded path: Tine checks that the file still matches what it read before it replaces it, and a save that would overwrite an outside change is refused rather than forced (see external edits below).
	- A page **rename** finishes once it starts; it is not rolled back. Tine writes the page under its new name and every page-link and tag rewrite that points at it, and removes the old file last. If a file cannot be written yet, the message says the rename finishes once it can be, and Tine keeps trying; if Tine stops in the middle, it finishes the rename on the next start. A crash while the new file also cannot be written can leave the page briefly without a file: its text stays in `logseq/.tine-trash/` or in Tine's crash-recovery copies until the write succeeds.
	- A page that still carries unresolved git or Fossil merge markers is never rewritten by a rename: its links keep the old name, and a message lists those pages so you can update them after resolving the merge.
	- Tine saves pending edits before a rename. A page whose edits cannot be saved stops the rename only if the rename would change that page, or its unsaved text mentions the old name; the message names it. Other pages keep their unsaved edits through the rename.
	- An Org file is rewritten only when Tine can reproduce it byte-for-byte; one it cannot round-trip opens **read-only** so the graph cannot be corrupted.
- ## External edits
	- Tine notices changes made outside it — Logseq, Syncthing, or another editor. Settings (**t s**) → **Files** → **Watch for external edits**: **Live (inotify)** (default, no idle wakeups) or **Poll (3s)** for filesystems where the OS watcher misses edits (some network mounts). Saved per device.
	- A page updates in place automatically, also while one of its blocks is open in the editor: the editor stays on that block, and closes only if the change deleted it (while you are composing text with an input method, the update waits until you finish). A page with unsaved edits is never overwritten: Tine skips that page in future saves and shows a banner with **Review**, which opens the panel at the top of the page. There you compare your draft with the disk version block by block and choose **Apply resolution**. An outside change that holds exactly your unsaved text (often a sync tool delivering Tine's own write back) is not a conflict: Tine accepts it quietly and still saves your edit. The **N conflicts** page lists such pages under **Unsaved drafts**.
	- Prefer to approve even clean external updates yourself? Turn on Settings → **Backups & recovery** → **Always ask before applying an external change**. Tine then holds the silent case and offers **Keep mine** / **Use disk version**; changes that already conflict keep their existing safer handling.
	- Returning to Tine asks the watcher for a fresh pass, covering network mounts, suspended apps, and sync tools that delivered no live filesystem event; typing waits until that pass is in. A large `git checkout`, `fossil update`, branch switch, or sync burst is grouped into one external revision instead of interrupting once per page. Changes inside `.git/` or Syncthing's `.stfolder/` are ignored.
	- If the system refuses live file notifications (for example the per-user watch limit is reached), Tine says so and checks for external changes every 3 seconds instead, retrying live notifications as it goes.
	- Files in `assets/` are watched too. An image replaced outside Tine — by an editor, Syncthing, Dropbox, or another Tine window — refreshes where it is shown, without reloading the page, and one deleted outside shows its missing-image placeholder. This also covers an `assets` link to a folder outside the graph that you have approved. An open PDF, audio, or video is not swapped while you use it; it shows the new file the next time you open it.
	- `logseq/config.edn` is live too. A change made in Logseq, a text editor, or delivered by a sync provider updates favorites, shortcuts, the home page, journal formats, and other shared settings during the session; reopening the graph is not required. A settings change made in Tine edits only its own entry, and is refused rather than written if `config.edn` is half-written or not a map, so a file still arriving from a sync provider is never overwritten.
	- For file sync between devices, run one app at a time on the graph where you can, and let conflict copies (below) catch the rest.
- ## Snapshots — automatic backups
	- **Backups of a moved or unavailable graph** appear when you open **Backups & recovery**, with the recorded path. That graph may be moved or unavailable (for example, a disconnected drive). Restore asks you to confirm that location and takes a safety snapshot of the current graph first. **Delete backups from this location** asks before removing those snapshots from this device: these may be the only backups of a graph on a disconnected drive. Backup archives are kept unchanged when a graph moves.
	- The command-line `tine serve` owner skips its launch snapshot when the newest backup zip is less than 6 hours old, so scripted edit/restart loops preserve the backup slots. The date comes from the zip's name; a future-dated zip does not suppress a snapshot. The app still takes its launch snapshot as usual.
	- A launch snapshot (in the app, or as a command-line `tine serve` with no window) copies every Markdown/Org page in the graph — pages and journals, and pages kept in other folders or at the graph root — plus `logseq/config.edn` and asset `.edn` sidecars, to a local folder **outside** the graph, once opening has gone quiet (a few seconds after startup finishes, at most three minutes) so the copy does not compete with your first page. Syncthing never syncs it. Binary assets, folders listed in `:hidden`, and Tine's own trash and backup folders are not copied.
	- Settings → **Backups & recovery** → **Snapshots to keep** (default 12) sets how many survive. A launch where nothing changed writes no snapshot, so the count covers changes to your graph rather than launches; the oldest beyond it are pruned. The snapshot taken before a restore is never pruned and does not count, and neither does one marked **Damaged** (it is removed once it is older than the oldest kept zip snapshot). Tine prunes only after it has checked a newer snapshot and confirmed it is safely on disk; on a disk that cannot confirm that, nothing is pruned and old snapshots pile up.
	- Backups have a size limit: the files a snapshot copies may total at most 512 MiB, with no single file over 128 MiB (binary assets are not copied, so they do not count). A graph over the limit is not snapshotted: Tine says the backup failed, writes nothing, and a restore or journal rename that needs a snapshot first does not run.
	- 1. Pick a snapshot under **Available snapshots** and choose **Restore**, then confirm.
	- 2. What you should see: Tine saves pending edits, snapshots your current state first, restores backed-up graph text to its original paths, restores config and sidecars, and reloads the graph — a mistaken restore is itself reversible. Pages created after the snapshot are moved into the restore's recovery folder under `logseq/.tine-trash/`, not deleted. Some snapshot folders from an older Tine cover only the pages and journals folders; such a one made under a different pages or journals folder setting is refused rather than restored into the wrong place. Zip snapshots, and the newer snapshot folders, cover pages wherever they live.
	- A launch where nothing changed since the newest snapshot writes no new one. A snapshot marked **Damaged** in the list failed its check and cannot be restored; pick another. One marked **Made by a newer Tine** can be restored only by that newer version.
- ## Where your backups are
	- Each snapshot is one ordinary `.zip` file (snapshots from an older Tine are folders; see below). You can open it with your system's archive tool, without Tine: inside, every file sits at its path in your graph (`pages/…`, `journals/…`, `logseq/config.edn`, asset sidecars under `assets/`), next to `tine-backup.json`, the list Tine checks the zip against. Snapshot names start with the date and time they were taken, in UTC. To get back a single page by hand, copy it out of the zip into your graph; Tine picks it up like any external change.
	- The zips are in Tine's app data folder, under `backups/<graph folder name>-<code>.zips/`, one folder per graph. Below, `<app id>` is `page.tine.Tine` for stable Tine and `page.tine.TineBeta` for Tine Beta.
		- Linux: `~/.local/share/<app id>/backups/` (Flatpak: `~/.var/app/<app id>/data/<app id>/backups/`)
		- macOS: `~/Library/Application Support/<app id>/backups/`
		- Windows: `%APPDATA%\<app id>\backups\`
		- Android and iOS: the folder is in the app's private storage, which a file manager cannot open; restore from Settings.
	- Snapshots made by an older Tine are folders rather than zips, in `backups/<graph folder name>-<code>/`. They stay listed and restorable and count toward **Snapshots to keep**, except folders in the newer folder format that another Tine build wrote: those are never counted or pruned.
	- Tine has no button that opens this folder; use your file manager.
- ## Recovering by hand with Tine closed
	- When Tine will not start, or you want a whole earlier state back without Tine, recover from a snapshot zip yourself:
	- 1. Quit Tine completely, every window, so nothing is saved over the files while you work. If a sync tool such as Syncthing or Dropbox serves the graph, pause it too.
	- 2. In the backups folder above, pick the newest zip from before the problem.
	- 3. Extract it into a new, empty folder, never directly over your graph. Delete `tine-backup.json` from the extracted copy: it is Tine's checklist, not part of your graph.
	- 4. Move your current graph folder aside (rename it; keep it until you are sure), then move the extracted folder into its place. Or copy only the pages you need from the extracted folder into your graph.
	- 5. From the old graph folder, copy over what snapshots do not contain: images and other binary assets, folders listed in `:hidden`, and Tine's trash in `logseq/.tine-trash/`. If your `assets` folder is a link to a folder outside the graph, the sidecars from the zip's `assets/` belong in that folder.
	- 6. Start Tine (and the sync tool) again. Tine reads the files like any external change.
- ## Git: automatic commits and sync
	- If your graph folder is in a git repository, Settings → **Graph** → **Commit changes to git** → **Commit automatically** makes Tine commit the graph's changes for you (the default is **Off**, and the choice applies to this device only). Tine commits after a minute without edits, at most once per interval (**At most every** 10 minutes by default; you can set any whole number from 1 to 1440 minutes), once more when you quit, and before and after a rename, merge, delete or backup restore, so each of those is its own commit you can undo with git.
	- If the graph is not in a repository, Settings says so and hides the control: create one in the graph folder first (run `git init` on a computer, or use a git app on a phone), then open Settings again. Tine never creates or clones a repository: on a phone, put one in the graph folder with a git app or copy it from a computer.
	- A commit holds every change git sees in the graph folder, including edits made by other programs; files your `.gitignore` excludes are left out. With automatic commits on, Tine adds two lines to the graph folder's `.gitignore`, each once and only if git does not already ignore those files: `.syncthing.*` for Syncthing's temporary files, and `logseq/.tine-*` for Tine's own files for this device, such as its trash in `logseq/.tine-trash/` (committed, the trash would stop two devices syncing one repository at the first deleted page). Tine tells you in a notice and in the git status in Settings. You can remove a line; Tine will not add it again on this device for this graph path, even after restarting or turning automatic commits off and on. A failed attempt is not retried automatically. Tine's commits always exclude Syncthing temporary files and Tine's own files, even if writing `.gitignore` fails. If an earlier Tine committed its own files, Tine removes them from git (not from disk) in a separate commit, "Tine: stop tracking its own device files", just before its next commit (until then `git status` may list them as changed); a sync never writes another device's copies, and conflict copies (`*.sync-conflict-*`) are still committed unless your own ignore rules exclude them. Tine changes repository config only when you choose the line-ending repair below. To keep another file out of the history, add it to `.gitignore`: a file you only untrack with `git rm --cached` is committed again. Tine pushes and pulls only with a sync option (below). When the graph is a subfolder of a bigger repository, only that subfolder is committed, and changes you staged elsewhere stay staged.
	- Commits use your git `user.name` and `user.email`, with the message “Tine: autosave” or a description such as “Rename page "old" to "new"”. Every 50 commits Tine packs the new ones together, so the repository does not fill with small files; it never rewrites what is already packed.
	- With autocommit on, Settings shows the branch Tine commits to and the last commit (its short hash and time). It also says when Tine can't commit and why: another git command holds the repository's `index.lock` (Tine waits; if it stays held for over 30 minutes, Settings names the file so you can remove it after a crash; an empty `index.lock` that has not changed for 10 minutes while Tine itself is not using git is almost always left over from a commit that was cut short, and Tine offers **Remove the stale lock**), a detached HEAD, sparse checkout, a `.gitattributes` filter such as git-crypt or LFS, a missing index (run `git reset`), unresolved conflicts, or on macOS and iOS a repository without `core.precomposeunicode`. A failed attempt shows as "Last attempt failed" with the reason.
	- If git cleanup fails, Settings says "Git cleanup is waiting; commits continue. Tine will retry automatically." Your commits continue to record changes; cleanup waits at least 10 minutes before retrying on a successful commit cycle. This status clears when cleanup succeeds and does not produce repeated toasts.
	- **Commit and sync on demand** and **Commit and sync automatically** also exchange commits with the branch's upstream (what `git push -u` or `git clone` set up), so another computer that syncs the same repository sees your changes. **On demand** syncs when you press **Sync now** in Settings; **automatically** syncs after each commit and once per interval as well. A sync fetches the remote, brings this device's graph up to its newer commits, and pushes your commits. When nothing changed on either side it costs one short request to the remote. Tine never merges, rebases or force-pushes. The line-ending repair below changes only this repository's `core.autocrlf`, when you choose it.
	- Sync needs the graph folder to be the repository's top folder (bringing in a bigger repository would change files Tine does not own), a branch with an upstream, and no line-ending conversion (`core.autocrlf`, or `text`/`eol` in `.gitattributes`). Otherwise Settings says why and offers only the commit options. Settings shows the remote's name and address, and the time and result of the last sync.
	- For an `https://` remote, press **Sign in** and enter your username and a personal access token that can read and write the repository (GitHub: Settings → Developer settings → Personal access tokens; GitLab: Preferences → Access tokens; Codeberg: Settings → Applications). Tine keeps the token in a private file on this device, never in the graph, the repository or Tine's settings; **Sign out** deletes it. A remote on this computer (`file://`) needs no sign-in. SSH remotes are not supported yet.
	- When this device and the remote **both have new commits**, each has commits the other lacks, for example after editing on two computers between syncs. Tine then stops syncing and changes nothing. Merge in git: press **Copy the git command**, run it (`git pull`) in a terminal in the graph folder, resolve any conflicts and commit, then press **Sync now** and Tine pushes the merge. Merging inside Tine comes later.
	- A sync waits rather than overwrite anything: while a page it would update has unsaved edits, while another program changed a file, or while another git command holds the repository, it tries again at the next sync. If a file it would update is a link, a submodule or staged differently, Settings names the file so you can fix it in git. When a problem needs you, or keeps coming back, a notice also appears above the page with a way to fix it ("Copy the git command", "Open the folder", "Sign in again") and a button to Git settings; it goes away once a sync succeeds.
	- On Android and iOS git works as on a computer, plus two moments a computer does not have. When you switch to another app, Tine saves your pages and commits them, at most once per interval (with the default 10 minutes, at most 6 times an hour; edits held back are saved and commit later), and, with **Commit and sync automatically**, pushes; it never starts bringing in changes while in the background. When you come back to Tine, **Commit and sync automatically** syncs at once. If the phone ends Tine in the middle of a commit or push, the repository can be left with a lock file such as `.git/index.lock`: nothing is lost, but Tine waits. Once that lock has not changed for 10 minutes, a notice (and Settings) offers **Remove the stale lock**; Tine checks the file again when you press it, removes only that file and then commits, and never removes a lock by itself. A lock on the branch, such as `.git/refs/heads/main.lock`, is never offered: after 30 minutes Settings names it for you to remove. On Android, shared storage cannot change only the capitalization of a file name in one step, so a rename by capitalization alone (`c.md` to `C.md`, yours or a pulled one) goes through a temporary name in Tine's own `logseq/.tine-respell` folder. If Tine is stopped in between, the page is back under its new name the next time Tine opens the graph; nothing is lost.
- ## Git line endings on Windows
	id:: e7ad234c-701e-4473-a6e3-111264be9655
	- Git for Windows normally converts LF line endings in commits to CRLF on disk (`core.autocrlf=true`). Tine's sync compares exact bytes and refuses that conversion, including `core.autocrlf=input`. If every tracked file's bytes already match the index and no attribute conversion remains, Settings → **Graph** → **Commit changes to git** and the sync notice offer **Turn off line-ending conversion for this repository**. It changes only `core.autocrlf` in this repository's `.git/config`, never global or system settings, and changes no graph file. A running sync retries without a restart; otherwise choose a sync option after the repair.
	- If files differ, the notice gives their count and one example. Do not just turn conversion off: the next automatic commit could record Windows line endings throughout your graph. Save your edits, close Tine and other editors, and pause other sync tools before these steps. Open a terminal in the graph's top folder. Keep it closed to new edits until the checkout finishes.
		- Run `git status --short` to review what will be committed. Run `git add --all` to stage your changes, then `git commit -m "Save notes before changing line endings"` to keep them in history. If there is nothing to commit, skip the commit. Run `git status --porcelain`; continue only if it prints nothing. If the commit fails, stop and fix that first.
		- Run `git config --local core.autocrlf false` to turn conversion off for this repository only. Then run `git reset --hard HEAD` to re-check out the current commit's files, now without conversion. This overwrites tracked files, so run it only after the clean-status check and with no new edits. Your committed edit stays in history and the branch stays at the same commit.
		- Run `git status --short` again: it should print nothing. Your edits are committed and the files now have the same line endings as their committed blobs (normally LF). Reopen Tine and choose a sync option in Settings → **Graph**, or press **Sync now** if already chosen.
	- A `.gitattributes` rule such as `text`, `eol`, `crlf`, `filter`, `ident` or `working-tree-encoding` still blocks sync even with autocrlf off. The notice names the rule and path. Resolve that conversion in git first and commit the result; removing autocrlf alone cannot fix it. Missing files, submodules and unreadable paths also need fixing before the button can be offered. Files intentionally committed with CRLF stay CRLF; this repair never rewrites history or changes committed content.
- ## Git: what changed since you last looked
	- The changes notice stays at the top while you scroll, so **Mark page seen** remains reachable even in the middle of a long page.
	- On a graph that is in a git repository, Tine marks what other people or tools committed to a page since you last left it. Open a single page: a thin bar in the margin marks each block that changed, a removed block leaves a line “A block was removed here” where it stood (click it to read the removed text), and the page header says “N changes since you last looked” while N is more than 0. Whenever there is a change, even a single one, **Previous change** and **Next change** in that header step through them in page order, from where you are; each scrolls the block (or the “A block was removed here” line) into view below the header and highlights it briefly, opening a folded parent on the way without changing the file, and “3 of 12” shows where you are, with “wrapped around” when a step crossed the end of the list. They never put a block into edit mode. The same two steps are in the command palette as **Next change since you last looked** and **Previous change since you last looked** with no key assigned (Settings → **Keyboard shortcuts**). Leaving the page (opening another page, closing its tab or pane, or quitting) marks it seen, so the bars are gone when you come back. The journals feed, the sidebar, a zoomed block and references show no bars.
	- It works only on git graphs, and it compares **commits**, not files on disk. An edit that was never committed (for example one made by an external editor while Tine's automatic commits are off) is invisible until it is committed. Your own commits never count: “You” is the identity Tine's own commits are made under (your git `user.name` and `user.email`), so with **Commit automatically** on, Tine's autosave commits don't appear as changes. If the repository has no identity set, only commits Tine made under its placeholder name count as yours, and the header tooltip says so.
	- The first time a graph is opened here, everything up to that moment counts as seen. Commits from others that arrive later (for example through Syncthing) show on every page they touch, including pages you have not opened yet. A block you edit yourself after it was marked loses its bar; a page with more than 200 touching commits since you last looked counts every change, yours included, and the header tooltip says so.
	- **Mark page seen** is in the page's actions menu and the command palette; **Mark whole graph seen** is in the command palette and Settings → **Graph**; **Forget seen state** (Settings → **Graph**) clears what this device remembers, after which every page compares against the moment you press it. The record lives on this device only, never in the graph and never synced.
- ## Trash
	- Deleting a page or journal moves the file to `logseq/.tine-trash/pages/` or `logseq/.tine-trash/journals/`, not permanent deletion. Its name gains a timestamp followed by `__`.
	- Duplicate journal files you trash and unused media from an orphan scan land there too, and discarded sync-conflict copies and a file's pre-resolution version go to `logseq/.tine-trash/conflicts/`.
	- To restore something, open the matching typed folder, remove the timestamp and `__` from its name, then move it into `pages/`, `journals/`, or `assets/` with your file manager. Tine picks it up like any external change.
	- Settings → **Files** → **Orphaned media** (**Scan for orphans**) can find media no block links to (a deleted block keeps its files, so unused media accumulates) and trash it, and **Empty asset trash** deletes *asset* trash permanently — page, journal, and conflict recovery files are always kept.
- ## Sync tools and conflict copies
	- Keep Syncthing or Dropbox on your graph — Tine is built to coexist with them. Two files that resolve to the same journal day are kept, not dropped: the day joins the **N conflicts** queue, where you fold them block by block on the day itself, and Settings → **Backups & recovery** → **Duplicate journal days** offers **Open**, **Merge**, **Rename**, or **Trash** per file.
	- A `*.sync-conflict-*` (or `(conflicted copy)`) file never appears as a page. Files carrying unresolved git or Fossil merge markers are also quarantined from ordinary saves rather than rewritten.
	- Both kinds appear in one **N conflicts** badge in the sidebar. Open a conflicted page to compare the two versions block by block: choose **Mine**, **Theirs**, or both for each differing block, accept a suggested **Merged** version when both sides edited separate parts of one block, then **Apply resolution**. A pinned notice keeps the review reachable while you scroll: tap it to unroll the review in place. Nothing is auto-merged or auto-deleted.
	- Choosing the **N conflicts** badge opens the **Conflicts** page: every page that needs a decision, grouped by source, with how many blocks are left ("—" when not counted). Click a page to resolve it, or shift-click to open it in the right sidebar and keep the list in view. **Discard copy** moves a provider conflict copy to the trash, including a copy whose page no longer exists.
- ## Journal files named by title
	- Tine does not silently rename journal files when a graph opens. If an otherwise valid journal uses its display title as its filename (for example `Jun 18th, 2026.md`), the day may look empty because the filename cannot be matched to its date.
	- Settings → **Backups & recovery** → **Journal files named by title** lists these files. Review the list and choose **Rename to date names**; Tine takes a snapshot first.
- ## Export
	- Settings → **Graph** → **Export HTML and read-only app…** exports your `public:: true` pages as a standalone site. Give the export a name and choose a destination folder outside the graph; tick **Include every page not marked public:: false** to export pages that carry no `public::` property as well. A page marked `public:: false` is never exported, not even with that box ticked or with `:publishing/all-pages-public? true` in `config.edn`, and its blocks never appear in another page's embeds, queries or references. A graph with no `public:: true` page exports 0 pages, and the result line says that only `public:: true` pages are exported. Nothing is uploaded, and your graph is not touched.
	- **Export…** in a query's header exports the pages its results live on as a standalone site. Pages marked `public:: false` and the exports page stay out even when the query matches them; the review lists what was left out and says when the export includes the page the query is written on. Readers see the pages, not the query itself, unless you tick **Include the query text**. Review the page list first; Tine writes the export to `published-queries/<folder>/` inside your graph. If that folder exists, choose **Replace** (the previous export is kept in recovery and its path is reported) or **Create a separate export**. A query about blocks exports **whole pages**, not just the matched blocks, and the dialog asks you to confirm that.
	- Queries inside a query export show only results on the exported pages; they do not report how many results were left out on other pages.
	- A query export carries referenced local assets in its own `assets/` folder, so you can move or share the whole export folder. Missing assets are reported as warnings. Settings → **Graph** → **Query export size limit** sets the copied-asset budget for this device (default **1 GiB**). An export that exceeds it stops before replacing any previous export, with **Adjust limit in Settings…** to raise it.
	- `published-queries/` output never becomes graph pages and is excluded from graph backups. Back up an export folder separately if you want to retain it.
	- Serve an export folder over HTTP (any static host, or `python3 -m http.server` inside it) to open it as a read-only app; opening `index.html` straight from disk, or adding `?static` to the address, shows the plain static site instead.
	- Sheets on an exported page (tables, boards and grids) come out as the same tables, boards and grids you see in the app, including formula columns, filters and aggregate footers: Tine computes them with the app's own sheet code before it writes the export, in **Export HTML and read-only app…**, a query's **Export…** and **Export to PDF…** alike. The command-line export (`tine export static` or `tine export live`) has no app to compute them, so it writes a sheet as the plain outline of its rows. A sheet that cannot be computed, or that changed while the export was being prepared, is written the same way with a visible note, and the export still succeeds. A table or board that shows a query's results is written the same way — the query's own columns and its rows on the page they came from — when the block holds just that one query; a result on a page the export does not publish is left out of the table (and of its counts and totals), and if the results changed while the export was being prepared the block is written as the query's usual result list instead. A query table's exported totals summarize only the rows it exports, so they can differ from the live footer's totals over the query's complete sample.
	- If a query exceeds the **Print query limit**, PDF export names the reason and stops before opening the print dialog. Narrow the query and try again. Starting another PDF export supersedes the pending export; only the latest request may open its printout.
	- Right-click a page title → **Export to PDF…** prints one page on a light background. It is offered on desktop only: printing is unavailable inside a mobile WebView, so Android and iOS do not show it. **Export HTML and read-only app…** works on every platform.
	- To find HTML export quickly, open the command palette and run **Export graph as HTML and read-only app…**; it opens the same Graph settings export control. The folder picker starts at your last successful export destination on this device. The result shows the exported site's path; on desktop, **Show in folder** reveals it in the file manager. Mobile keeps its existing folder picker behaviour and does not offer the desktop reveal action.
	- Export cleanup removes selected links, tags and emphasis from ordinary text. Text inside inline code and fenced code stays literal in Text, OPML and HTML exports, even when it contains `[[links]]`, `#tags` or emphasis markers.
	- **Copy / export as…** on a block or page offers **Plain text** (without formatting markers) or **Markdown** / **Org** (with formatting preserved), then Text / OPML / HTML destinations with cleanup and depth controls. Markdown, Org, HTML and OPML resolve block references and expand page and block embeds, without adding source captions. Embedded outlines keep their children; expansion stops after five nested embeds. Internal properties such as `id::` are hidden. Text exports keep user properties as `key:: value` unless **Remove properties** is selected; page properties are omitted.

- ## Share pages
	- Share a page, or the pages a query selects, as a folder export in your graph or as an encrypted link: see [[Features/Share pages]]. Nothing leaves your device until you confirm in the Share dialog.
