- # Share pages
	- Share a page, or the pages a query selects, in two ways. **Folder** writes a static site and read-only app into your graph folder. **Link** uploads an encrypted copy to a secret GitHub gist and gives you a link anyone can open in a browser. Both start from the same **Share** dialog and both leave a definition on the **Exports page**, so you can repeat or update them later.
	- In the read-only app or a quick-share link, use a bullet's fold arrow to expand or collapse its children without changing the graph. Your viewing choices last while browsing between pages; reloading restores the original folds.
	- The static HTML version starts with the original folds too. Click the arrow beside a folded bullet to open or close it; this also works with JavaScript turned off.
- ## Start a share
	- **Share** opens from the share icon in the top bar (in a narrow window it is **Share this page** in the **···** menu), the share icon beside a page title, **Share…** in a page's **⋯** menu and right-click menu, and **Share…** (or the share icon) on a query block. It shares the page you are looking at; from a query block it starts from that query.
	- Choose **This page** to share just that page, or **A query starting at this page** to pick the pages with the visual query builder (edit the query and the live preview shows which pages it selects). **This page and its neighbours** is listed as coming with graph queries.
	- The review lists the pages that will be shared and, separately, the selected pages that are left out: a page marked `public:: false` and the Exports page are never shared, and the review says which and why. It also says when the selection includes the page a query is written on. **Include the query text** is off, so readers see the pages and not the query.
	- Under **Where to share**, choose **Folder** or **Link**. **Link** is greyed out with "Coming soon" until the compatible reader is deployed for your build.
- ## Share into a folder
	- **Folder** exports a static site and read-only app into `published-queries/<folder>/` in your graph, the same export as a query's **Export…**. You name the folder on the next step.
	- After a successful export Tine saves the selection as a definition so you can repeat it. From **This page** or a query you built in the dialog, it adds a query block with `export:: <folder>` to the **Exports** page, which Tine creates on first use (marked `tine/exports:: true` and `public:: false`, with a block listing every definition; if you already have a page called Exports it uses Exports 2). From a query block you did not change, it adds `export:: <folder>` to that block. Open **Share…** on a definition again and it shows the same selection. Nothing is exported again until you choose Export.
	- **Re-export** on a folder definition opens its review with **Replace** selected, using the same folder under `published-queries/`. Confirming keeps the previous export in recovery. There is no Delete action for folder exports.
- ## Share pages with a link
	- Choose **Link**, then **Connect GitHub** the first time. Tine asks for permission to create and delete gists; it only touches the shares it made. You enter a code on GitHub's device page; no password is typed into Tine. No GitHub account? On GitHub's sign-up page choose **Continue with Google**.
	- Review the pages and size, then choose **Create link**. The full source text of every shared page is included, including properties hidden from display, relative page paths, linked page names and attachment file names. Pages marked `public:: false`, hidden folders, the Exports page and other pages outside your selection are left out. Images and other files are not included. Edits after the preview require **Refresh**; creating a link shares the reviewed copy.
	- The key is in the link, after `#`. Anyone with the whole link can read the shared pages in a browser, without a GitHub account. Keep it private if the pages are private. GitHub receives encrypted text; tine.page's reader receives the key and plaintext. Both services see your network address when contacted, and GitHub sees the share's size and dates. The reader opens remote media only as links. Every shared page opens under a "User content · Shared by a Tine user" banner with a **Report abuse** link.
	- The graph records `tine.share:: <login>/<gist_id>` on the definition, without the key. The key stays on this device.
- ## Update, delete, and manage shares
	- Choose **Re-share** on a share's query on the **Exports page**, or share that query again, to update the same link. Review **+N new / −M gone** and the changed page names before confirming; nothing is uploaded until then. GitHub keeps old revisions: re-sharing does not remove previously shared text. Readers may see the update after about five minutes. Without the key on this device, choose **Re-share as a new link**; the old share stays separate.
	- **Update all** beside the Exports page title prepares folder exports and quick shares together. Folder previews show the page count and pages left out, plus **+N new / −M gone** when the previous export's snapshot can be read; quick shares show **+N new / −M gone** and collapsible changed page names. Nothing is written or uploaded until you confirm. Updates run one after another, and each result is shown even if another export fails. Folder exports work even when quick share is off or disconnected. Definitions without a key on this device, pending shares and preparation failures are listed as skipped with a reason. Quick-share previews are held in memory up to a fixed total size (24 MB); if a very large batch exceeds it, the remaining shares are skipped with that reason and can be re-shared after this batch.
	- **Delete** removes the hosted gist; it cannot remove copies readers saved, forks, clones, caches or GitHub backups. Its link stops working within about 5 minutes (GitHub caches the file that long), and a definition the share added to the **Exports page** goes with it; a share made from your own query block only loses its `tine.share::` line. You can Delete from a share's query on the **Exports page**, after a confirmation, even when its key is on another device: connect the GitHub account that owns the share. **Forget** removes this device's key and record; it does not delete the gist. **Disconnect** removes this device's GitHub connection; revoke Tine's permission in GitHub's Applications settings if needed.
	- **Settings → Sharing** (shown when sharing is available in your build) lists the links made on this device with **Copy link**, **Check**, **Delete** and **Forget**. **Check** asks GitHub whether an upload whose result was uncertain went through. **Find shares on GitHub** lists Tine shares in your account that this device has no record of; you can delete them, but cannot recover their keys. **Pending in this graph** lists query blocks marked `tine.share:: pending/…` (an upload that was not confirmed); **Check** finishes the ones this device recorded, and **Remove marker** clears one that no device is still uploading.
- ## Create one yourself
	- 1. Open a page and choose the share icon in the top bar.
	- 2. Leave **This page** selected and choose **Folder**, then **Export to folder…** and name the folder. What you should see: a `published-queries/<folder>/` export and an **Exports** page with one definition.
	- 3. Open the share dialog again, choose **Link**, and **Connect GitHub** (once). Review the pages and choose **Create link**.
	- 4. Open the copied link in a private browser window. What you should see: the page, read-only, under the "User content" banner.
	- 5. On the **Exports** page choose **Delete** on that share and confirm. What you should see: the definition disappears, and the link stops working within about five minutes.
