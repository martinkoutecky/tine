- # Command line
	- The installed desktop program also has a small command-line interface. Run `tine --help` for the current command list and `tine --version` (or `tine version`) for the exact build version.
- ## Open Tine
	- `tine open GRAPH` opens a graph. The older shorthand `tine GRAPH` remains supported. If Tine is already running, the graph opens in a new window of that instance.
	- `tine capture` opens Quick Capture. The older `tine --capture` spelling remains supported, so existing desktop shortcuts keep working.
	- `tine --debug` turns on the diagnostic log for that run, exactly like `TINE_DEBUG=1`.
- ## Publish a graph
	- `tine export static GRAPH --output PARENT` writes the static HTML publication. `tine export live GRAPH --output PARENT` writes the read-only Tine app and keeps the static HTML site as its no-JavaScript and `file://` fallback.
	- `PARENT` must be an existing folder outside the graph, given as an absolute path. Tine creates one new child folder in it, named after the graph (or after `--name`), and refuses to replace an existing folder of that name.
	- Publication follows the graph's existing privacy settings: only pages with `public:: true` are included, unless `:publishing/all-pages-public?` is enabled. Add `--all-pages` to override that selection for one export.
	- Example: `tine export live ~/notes --all-pages --output ~/Sites --name "My notes"`
	- A live export opens on the configured home page when it is exported, then **Welcome to Tine**, then the first exported page. Use `--home "Page name"` to choose explicitly; a home page that is not exported is refused.
- ## Check a graph
	- `tine doctor GRAPH` reads and parses the graph, reports how many pages and journals it found and the configured home page, names every unreadable page and every page name claimed by more than one file, and does not change the graph. It exits with status 1 when it finds a problem.
- ## Read your graph from a terminal
	- On Linux, macOS and Windows, the read commands below do not change notes. They ask the graph's owner, so `tine page show` and `tine journal` include unsaved edits when the app holds that page; other reads use the graph's indexed view.
	- Choose a graph with `--graph GRAPH` (or `-g GRAPH`) on each command. Otherwise Tine uses `TINE_GRAPH`, then the nearest folder around your working directory with a `logseq/` subfolder. Example: `tine page show "Project notes" --graph ~/notes`.
	- `tine status` shows whether the app or `serve` owns the graph and what it is doing.
	- `tine page show "Page name"` reads a page's outline. `tine journal` reads today; `tine journal 2026-10-13` reads a specific day that already exists.
	- `tine block show UUID` reads a block and its descendants using its persisted `id::` UUID. `tine refs "Page name"` shows linked references; `tine refs UUID --block` finds references to a persisted block id.
	- `tine search "meeting"` searches page names and block text as the app does. `--pages N` and `--blocks N` set the result limits; `0` switches that category off.
	- `tine query '(task TODO)'` runs the text inside a Logseq simple or advanced query macro. `tine query "task = 'TODO'" --tql` runs the text inside a Tine query macro. [[Features/Queries]] explains the query forms and their supported scope; read diagnostics when a query cannot run whole.
	- `tine pages` lists existing pages, including journals. `tine pages --namespace Projects` limits it to that namespace and its descendants; aliases and names that only appear in references are not listed.
- ## Write from a terminal (scripts and AI agents)
	- These commands change notes, through the same guarded save the app uses. They are meant for scripts and AI agents working beside you; every block they create is marked with an `author::` property so you can see what an agent wrote.
	- A page read prints each block with a **handle** such as `2.1~k7f2ab`: its position and a short fingerprint of its text. Name a block as `"Page name/2.1~k7f2ab"` exactly as printed, or by its `id::` UUID. If the block has changed or moved since the read, the command refuses with `stale` instead of guessing; read the page again.
	- `tine add "text" --page "Page name"` appends to a page, creating it if needed; `--journal` appends to today's journal and `--journal=2026-10-13` to that day. `--under BLOCK`, `--after BLOCK` and `--before BLOCK` place the new blocks next to an existing one. The text can hold several blocks with `- ` children; `-` reads it from standard input. New blocks get `author:: agent`, or the name in `--author NAME` or `TINE_AUTHOR`.
	- `tine edit BLOCK "new text"` replaces a block's text as typing it would; its children and hidden properties stay. `tine prop set BLOCK key value` and `tine prop remove BLOCK key` change one property. `tine move BLOCK --under|--after|--before TARGET` moves a block with its children on the same page. `tine delete BLOCK` deletes a block with its children and says how many block references elsewhere it leaves broken.
	- `tine page create "Page name"` creates an empty page and refuses an existing page or alias. `tine page rename "Old name" "New name"` uses the app's rename, rewriting references and namespace descendants; an existing destination refuses, so confirm merges in the app. A page's `title::` is its identity even when its filename differs. Open windows refresh the renamed page and its references.
	- `tine page delete "Page name" --yes` (or `--force`) moves the page to graph trash and prints the count of broken page and block references. Without confirmation it refuses. `--rev` guards deletion against the bytes you read.
	- `tine ref BLOCK` prints `((uuid))`; `tine embed BLOCK` prints `{{embed ((uuid))}}`. Both ensure a durable lazy `id::` first, as Copy block ref does, preserving the block's author. They print syntax to reuse; they do not insert a new block.
	- Page rename is graph-wide: `--rev` and `--run` (including `TINE_RUN`) refuse before changing anything. Create, delete, ref and embed support runs. A rename error marked `uncertain` means inspect the graph before retrying.
	- **With the app open:** text you have typed on that page is saved first, so the command works on what you see, and an open window shows the change at once. If you keep typing on that block while the command runs, it refuses with `stale` rather than overwrite you.
	- Add `--rev REV` (as `page show` printed it) to write only if the page has not changed at all since that read.
	- A write prints `written PAGE rev REV` and the handles of the blocks it created or changed, so a script can chain the next command.
- ## Keep an agent's work in git (runs)
	- If the graph folder is a git repository, an agent can group its writes into a **run**: `tine run begin` checks the repository and prints a run id. Every write made with `--run ID` (or `TINE_RUN=ID`) is committed right after it is saved, for that one file only, under the agent's name (`--author NAME` or `TINE_AUTHOR`, else `agent`). If the file had edits of yours that were not committed yet, they are committed first under your own git name, so your work never ends up inside the agent's commit.
	- `tine run show ID` lists the run's commits. `tine run end ID -m "summary"` squashes them into one commit, but only when none of them is pushed, on another branch or tag, or mixed with other commits; otherwise the commits are left as they are and the reason is printed.
	- `tine run revert ID` undoes the run's edits, newest first, as one change per page. A block you changed since the agent did keeps your text and is listed, so nothing of yours is lost.
	- A run never touches files it did not write. It refuses before writing when the repository is in the middle of a merge or rebase, HEAD is detached, or the page has a Git `filter`, `ident` or `working-tree-encoding` attribute: committing its raw bytes could expose plaintext or bypass conversion. Tine never runs external filters. If a commit fails after a save, the write is kept and a warning says it was not committed. A branch checkout while the commit is preparing also produces that warning; Tine leaves both branches and the new branch's index alone.
- ## Who owns the graph?
	- When the app has the graph open, it answers these commands. With no app holding the graph, a read or write command automatically starts `tine serve GRAPH` in the background. You can also run that command yourself in a terminal; it owns the graph without opening a window, takes a launch snapshot unless the newest backup zip is less than 6 hours old (see [[Reference/Files, external edits, and backups]]), and exits after 30 idle minutes. This keeps scripted edit/restart loops from filling the backup slots. A future-dated zip does not suppress a snapshot.
	- When you open that graph in the app, `serve` finishes admitted work, stops and hands over ownership. The app shows **Finishing the command line's work on this graph…** while it waits. If the handover has not finished after 60 seconds, opening fails and names `tine serve GRAPH --stop`; the app does not take ownership on a timeout. Read commands retry through a busy handover for up to 30 seconds.
	- `tine serve GRAPH --stop` asks the command-line owner to finish and exit. It cannot stop an app owner.
	- Windows supports the same read and write commands, automatic `tine serve` startup, handover to the app and `tine serve GRAPH --stop`, using a private named pipe for your Windows account. Add the folder containing `tine.exe` to PATH, or run it by its full path. Quote graph paths with spaces, for example `tine page show "Project notes" --graph "C:\Users\me\My notes"`. An unsafe owner directory or occupied pipe refuses with `owner-unsafe` (exit 5); the app can still open without a command endpoint.
	- Android and iOS have no command-line interface.
- ## Output for people and scripts
	- Read and write commands print text to stdout by default, with outline addresses such as `1.2` for a second child. Add `--json` for a single JSON result on stdout with schema `tine.cli/1`, for example `tine pages --graph ~/notes --json`.
	- Successful commands exit 0. Failed commands print errors to stderr; `--json` makes owner and connection errors a JSON error envelope there. Invalid usage exits 2, a missing or ambiguous page/block exits 3, a still-busy owner exits 4, endpoint/startup failures exit 5, a `stale` or refused write exits 6 and a write whose draft could not be saved exits 7 (in both cases nothing changed), and a write whose outcome is pending or unknown exits 8: read the page before retrying. Check the exit status and read any diagnostics or truncation notices before treating results as complete.
	- The [command-line output contract](https://github.com/martinkoutecky/tine/blob/og/docs/contracts/cli-output.md) documents JSON fields, limits, error codes and the full exit-code table.
- ## Full reference
	- Every command and subcommand has `--help`, for example `tine export live --help`. Linux `.deb` and `.rpm` packages also install the same generated reference for `man tine`.
