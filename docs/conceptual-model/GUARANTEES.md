# Guarantees and certification boundary

This document and SPEC.md describe the same conditional acceptance model. The core decides one name request on page files; a name-selected merge is included. Settings completion and day opening/creation are stated in Part III. Core imports neither views nor chapters. A separate physical file merge is outside this model. The
implementation must run the same merge writer and the same content/save checks on that entry point.
No claim about application conformance follows from the Lean build.

## Part I — Core

### Decision and safety

`selection_total`, `selection_deterministic`, `decision_total`, and `decision_deterministic` establish
one outcome for fixed total reader, configuration and producer parameters. The outcomes are done,
the sole confirmMerge question, or a named refusal. They do not promise writer success. O3 gives
physical holders precedence, refuses several holders and alias-held destinations, and admits the
source's own alias directly. A source without a file creates none.

`unattended_no_question`, `unattended_no_merge`, `decision_unattended_no_question`, and
`done_unattended_no_merge` cover unanswered and supplied-answer requests alike. A supplied confirmation
cannot authorize an unattended merge. Cancellation and an answer without a question are refusals.

`done_o4` combines every semantic O4 safety clause with actual-output content equality to the
input-only expected function; `title_rebinding` exposes its prefix/kept-tail/nested-reference equation.
`done_name_safety` supplies the semantic safety clauses for every done outcome. Its conclusion has no
checker-success premise: input and output path well-formedness; no capture of a file- or alias-claimed identity except the survivor or the source identity
renaming onto an alias claimed only by its own file; a child receives no such exception; reference-only destinations are free;
clean touched names before and after; no new twin pair; claimed own-child exclusion; matching merge formats and conflict-free merge operands;
truthful supported-domain membership and unchanged-save stability for touched Org files; no rewritten
nested reference in the replaced title prefix; original-other-file folded-path freedom and actual
output folded-path freedom; title/claim identity and verbatim movement of conflicted files.
`unchanged_child_touched` and `declared_alias_touched` expose the inclusion of unchanged non-day children/aliases.
Namespaced aliases declared by any page are included. A day under the source is excluded and stays.
A merge whose prescribed leftover loses a reference occurrence under the same reader is refused
as `leftoverReference`; `BeforeNameSafety.leftoverReferences` is derived on every done request.

`done_stationary_twins_opening` preserves the optional physical opening path at **every** previously
contested identity. Its only premises are done and prior contestedness; it adds no preservation or
parser-coherence hypothesis. `done_all_day_files` gives, for every original physical day claimant, a
corresponding output with the same day and path. `fileless_no_creation` plus `done_pair_observations`
give retained-input cardinality and output-origin pairing for a fileless source, including namespace
children that themselves have files.

### Native text and conservation

`Header.key` is an optional parser-normalized property key, independent of typed name sites.
Built-in properties retain their keys without a key site; non-property header text has none.
A truthful reader supplies the same name in the key field and its property-key site where one exists.
`headerKey` reads the field (`getD ""` only totalizes absent keys; a property has a key).
`mapHeader_key_site` and `mapHeader_key_no_site` prove the input-only expected-key equations:
use the first key site's `siteResult` name, with O7 spelling and all O2/O7 exceptions, or preserve
the input key when no key site exists. Erasure retains the field. Allocation compares transformed
keys; P2 compares these expected fields against keys independently read from the actual output.

There is one ordinary block observation: depth, raw LF-normalized/dedented content and source-header
attachment. Quote framing remains in content. There is no special leftover/payload observation.
A title has one enclosing native span and an ordered literal/reference decomposition; the inner sites
remain ordinary Reading occurrences. Admission checks its whole raw value, part concatenation and
nested native locations, besides all actual native site slices. `independentSites` checks uniqueness
between independent atom inventories and sibling nested sites, allowing an enclosing title and its
inner reference to have identical spans. Report identity is path/span/kind.

`done_p1`, `p1_splice`, and `p1_unrewritten` establish exact single-line splicing outside a merge pair:
original gaps and tail, monotone bounded nonoverlap, one maximal title envelope, single-line old slices
and replacements, and byte identity for no edits. `done_reading` and `done_pair_observations` bind every
actual file's path/directory/format and non-header observations exactly to the input-only expected
function, and a merged survivor’s header to the exact occurrence-preserving permutation. Outside a merged survivor there is a single header order. `ContentMatches` retains every header occurrence. Every block, including the leftover, retains exact typed observations, raw characters, depth and attachment. `leftoverUnkeepable` compares the input-derived demoted reference sequence with its same-reader reparse before selection succeeds. That function
has no output, producer or writer-report argument; `expected_save_independent` also excludes save
callback influence.

P4 applies to content after legal O1/O2/O7 transformations. `expected_merge_conserves` proves:

- A permutation of survivor headers and joining entries, with no promised order; a permutation partition of every source header
  occurrence into joining/leftover destinations, ordered sublists and exact per-entry counts.
- Survivor blocks, the optional ordinary leftover, then source blocks with unchanged depths. Nonblank pre-block content is already the reader’s first top-level block.
  Source header children attach below that leftover; no leftover with header children is refused.
- There is no separate preamble observation or merge-time conversion. Blank lines and bare structural bullets do not create
  leftover blocks or content-bearing header entries.
- Survivor-first alias union, and exactly one declaration with members when that union is nonempty.
  Memberless declarations are other header text. `alias_union_order`, `alias_union_coverage`,
  `alias_union_nodup`, `alias_union_count`, and `alias_union_first` prove order, coverage, exact identity
  multiplicity (one or zero), and first semantic-name representative. They do not preserve an alias
  token's raw escape syntax inside a merge pair.
- `leftover_exact_content` states the exact raw block string: empty first line, newline-separated
  leftover header lines, with ordinary Org quote framing in Org. It requires truthful title decomposition
  for arbitrary supplied header values; `expected_header_faithful` proves that condition for the model's
  transformed inputs, without assuming an output demotion law from an adapter.

`done_p4` transfers those sequence/partition facts through P2 to the actual survivor observation. Its blocks equation is exact, including every typed site; raw content multiplicity, position, depth and attachment remain exact. The source allocation’s order is still promised even though the merged header order is not.
`done_block_content_count` is the accepted-output consequence on the ordinary reader's block-content
strings, preserving repetition and accounting for the novel leftover; `done_alias_content_count` is
exact alias identity multiplicity on the actual output. `semantic_block_content` proves that coordinate
and literal-segmentation normalization changes no raw observed block string. The merge statements name
the selected source/survivor and their output pairing; those are intrinsic merge-case antecedents,
not hypotheses that a writer preserves arbitrary content.

`done_stable`/`accepted_stable` establish whole-File equality under the supplied unchanged-save callback
for every changed output. This includes both path and bytes and thus every deterministic re-observation.
It does not promise unchanged-save stability for an unrelated unchanged file, protection after later
edits, an OG trimming save, or universal writer success.

`fixed_site` and `site_classification` partition ordinary site handling into mapped, fixed, skipped,
unspellable and normalized-key cases. Titles use the enclosing rebind rule and nested suffix mapping.
`done_exception_locations` proves that every exceptional input site has its actual report and that
report path/span/kind identities are distinct. `accepted_reports_distinct` is the underlying admission consequence.

### Reader laws and non-vacuity

The bounded reader is an independent native-input table generated by a small parser, recursively closed
over **every** observation row. It is used for inputs, outputs and Reading fragments. It does not accept
writer wishes as observations. All native records have kernel-checked read equalities, actual byte-span
geometry, complete title-part concatenation/location checks, and same-reader occurrence-sequence laws.
`fixtures_reader_laws` covers every fixture input/output/control; `reader_fragment_law`,
`reader_geometry_law`, and `reader_title_parts_law` cover the recursively closed native table.
`reader_ownership_law` checks that a block attached to a structural header has a header owner. The generator checks disjoint native pre-block/header-child ownership before normalizing pre-block text into an ordinary first block.

The matrix includes plain and merged linked-title requests, coincident title/reference spans,
reference-only destinations, pinned slash-date children, own aliases, preamble blocks, flexible joining,
blank/bare-bullet headers, spellable and unspellable Org tags, capture/contest/own-child controls,
conflicted merge operands, refused Org leftover lines with hidden references, reference-preserving Markdown leftover content, a permutation reversing the source header sequence while preserving the survivor sequence, distinct built-in keys joining together, built-in key collisions and non-collisions, a key collision after O7 renaming, split alias declarations, missing header entries and changed leftover characters (the Org input refuses early; its Markdown counterpart reaches P2).
All strings are **model fixtures**, not application or parser-oracle executions. Physical file merge
is outside the model and has no current admission theorem.

Fixture adapter facts: native syntax/roles/content are the generated bounded parser's; ASCII lowercase
keys and folded paths; two identifying date spellings (including one slash date); ordinary site codec with Markdown tag wrapping
and the specified unspellable contexts; native key spelling; percent/slash leaf encoding (`%` to `%25`, `/` to `%2F`); declared path
parent/extensions; actual conflict-marker flag; save=id. Finite truth does not establish production
parser/save fidelity. The fixture-supported predicate is exactly its finite native-table domain; the
production supported predicate must instead describe the frozen 15k domain.

### Undischarged interpretation obligations (D-20261106-UA)

**P/configuration and native parser.** Ordinary normalization/date factorization, actual day values,
filename-day extraction independent of displayed titles, directory/stem/title meaning, unsigned UTF-8
path order, URL/nonblank/namespace interpretation. A complete truthful parse must supply all headers,
member-bearing declaration counts, native form/key/value/content, raw blocks/depths/header
children, typed sites (including nested title references, queries/macros/Org links) and truthful native
spans. Same-reader row reparsing must preserve occurrences. False extraction, omitted opaque content,
wrong contexts, or narrowed supported-domain membership can make checks misleading or overly refusing.
These obligations are not assertions that an adapter can assign missing quote/title observations: those
representations are explicit, checked and jointly inhabited in this model.

**N/codecs and paths.** Representability, key spelling, wrappers, directory/extension/encoding and actual
filesystem folding must be the real ones. Returning none for an ordinarily spellable site creates a
false O7 exception. Geometry checks do not establish completeness of parser sites. Identifying survivor
spelling is tested, not universally assumed available.

**S/save.** The callback must run the complete production unchanged-save path with descendants, options,
serialization and naming. The model tests equality; the bounded identity callback proves inhabitation,
not production fidelity. A lossy callback may refuse an otherwise available writer candidate.

**W/writer.** A fixed total producer supplies the actual candidate or failure. No universal native writer
existence or success theorem is claimed. The expected function does not see its candidate. A production
writer must construct candidates satisfying the checked properties for the intended non-refused domain.

**Host.** Publish the exact checked bytes through audited revision/lock/crash-safe storage and deliver
actual located reports. Page soundness proves no I/O, concurrency or crash protocol. Settings are a
separate chapter step and their bytes are outside P1–P4.

Every boundary may be too strong if the actual parser, codec, save implementation, evaluator or host
disagrees. A production adapter must discharge these interpretation facts by code/conformance evidence;
the finite matrix cannot discharge universal production fidelity. Formal done/merge/source/date/member/
freshness/comparison antecedents remain visible in the theorem statements and the headline inventory.

### Restructuring and scope proofs

`selected_pre_safe` derives before safety from public selection. `post_paths_nodup` and
`post_no_new_twins` derive the two removed actual checks from input well-formedness, checked
cardinality/folded paths, actual identities and touched cleanliness. These conditions are established
by the request path; no new caller premise appears on any done headline. Historical comparator
`Refactor4.post_equiv` preserves exact refusal precedence, including distinguishing the unreachable
old newCollision reason. Byte injectivity derives P1's no-edit identity; the earlier post check supplies
the removed P1 cardinality test. Both result-schema and Candidate round trips and whole-request
commutation are proved. The historical comparators are proved against the exact round-4-equivalent
source and the exact page-projection source before the round-5 merge changes. The final historical comparison shares the final core merge predicates; it is a refactoring proof,
not a claim that the intentionally changed merge outcomes equal round 4.

### Size and certification

The rule-unit ledger, counted with the inherited r6 rules, gives **540 U core,
85 U views, 28 U chapters**. The observed key field and its expected transformation cost 4 U.

Reading/view/day declarations keep their statements and proof bodies; day creation is charged to

confirmation and application conformance are separate matters.

## Part II — Views

Query evaluation/projection, namespace tree display, Linked References and graph views keep their
retained headlines and qualifications. V03/V04 are display rules, charged here; the core retains
namespace closure. No core module imports the view layer.

**G/views.** Truthful query IR, opaque predicate evaluations on the actual graph, ancestry/depth and row
classification. Reading/views theorems describe those supplied inputs; evaluation is not proved against
an application parser. There is no new positivity, stable-predicate, unchanged-alias-component or
fixed-parent restriction. Reading self-opening retains its original identifying-name premise; The Day files chapter retains claimant/freshness premises and does not produce a real writable filename by proof.


## Part III — Chapters

### Settings

`finishSettings` is a function of the core's done page result and the previous settings. Its callback
is an honest all-or-none record-write outcome. `done_settings_atomic` proves that the returned
SettingsStep is either the complete intended record with updated status or the complete old record
with failure status. `favorites_rename`, `favorites_merge`, `favorites_page_follows`,
`home_merge_stays` and `home_other_follows` state the unchanged mapping, whole-list first-name merge
deduplication and exact-source home exception. Alias-union theorems provide the shared first-name
coverage/order/multiplicity facts. `Refactor4.decide_pages_projection` proves that the core page
result is exactly the page projection of the combined result, for every settings record and success
function, without additional caller assumptions. `decide_chapter_equiv` also preserves the complete
settings completion against the historical algorithm.

**H/host and settings.** Publish the exact checked bytes through audited revision/lock/crash-safe storage;
return genuine located reports and honest separate all-or-none settings I/O/status. On failure the full old settings record remains. The pure model performs no I/O.
Settings bytes are outside P1–P4. Favorites map then retain first names on merge; the exact-source home
entry stays while descendants follow. No universal persistence, concurrency or arbitrary-later-edit
claim follows from a pure done result.

### Day files

`Journal14.ensureJournal` remains built and proved. `ensure_reuses`, `ensure_original_files`,
`ensure_created_exact`, `opening_cons_fresh`, `ensure_idempotent` and
`ensure_any_claimant_reuses` retain their original statements and proof bodies. Reuse finds physical
claimants independently of alias opening; creation requires the correct journals directory/day,
empty text, well-formed original paths and an unoccupied proposed path, retaining all originals.
Repeated ensure is idempotent. The model does not construct a real writable filename or prove host I/O.
Existing-day identity and preservation are still core; no rename/merge calls day creation. OUT01's
history-free snapshot rule stays in core.
