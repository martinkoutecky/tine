# Localization (tine#107)

Tine's interface text is localized; graph content never is. This contract says
what is translated, who formats it, where the choice lives, and the checks that
hold it. Design and rationale: the i18n campaign's DESIGN (decisions D1–D13,
revisions 2 and 3).

## What is and is not translated

- Translated: Tine's own interface text (menus, settings, commands, notices,
  dialogs, the tray menu, the startup screen).
- Never translated: anything from the graph (page and journal titles,
  properties, markers such as `TODO`, Markdown, query syntax), plugin-authored
  text, and OS-originated text. Such text crosses as `rawText(...)`.

## Catalog

- Fluent files under `src/i18n/locales/<tag>/<area>.ftl`. `en` is the source and
  is complete; another locale may be partial and falls back to English message
  by message, and also on any formatting error.
- `meta.ftl` per locale: `-locale-name` (the endonym the picker shows) and
  `-locale-matches` (the system language tags it serves). Adding a locale is
  catalog-only: the registry is generated.
- Message ids are semantic and stable, kebab-case with an area prefix. A
  command's message is `command-` + its id with `/` replaced by `-`.
- Supported Fluent: messages, attributes, terms, message and term references,
  `NUMBER`, `DATETIME`. A translation may use a subset of the English
  message's variables, never another.
- `shell.ftl` holds the only text native code shows. It is literal text only (no
  variables, references or selectors), compiled to
  `src-tauri/src/i18n_shell.gen.rs`; native code selects strings and never
  formats.
- Staleness: `<tag>/.source-hashes.json` records, per message, the hash of the
  English message and everything it references. A translation whose recorded
  hash differs is stale. Only `scripts/i18n-accept.mjs` writes this file.
- Derivatives (`src/i18n/messages.gen.ts`, `src-tauri/src/i18n_shell.gen.rs`)
  are generated by `scripts/i18n-gen.mjs` and checked current by the catalog
  test.

## Formatting

- The frontend is the only formatter (`src/i18n/index.ts`). `t(id, args)` and
  `render(text)` read the reactive active locale, so a Solid computation
  re-renders on a language change.
- Stored state and tables hold `Msg` (`msg(id, args)`) or `RawText`, never a
  resolved string; only reactive consumers resolve.
- The literal ratchet (`scripts/i18n-literals.mjs`, baseline
  `src/i18n/literals-baseline.json`) parses `src/**/*.ts(x)` and `index.html`
  text nodes and attributes. It fails when a site appears whose (file, sink
  kind, nearest enclosing named owner, normalized text) is not in the
  baseline, counting every text with a two-letter word, lower-case included,
  at the sinks it lists (JSX text and fragment/conditional string children,
  `title`/`aria-label`/`placeholder`/`alt` and other accessible-text attributes,
  component `label`/`hint`/`tooltip`/`fallback` props, toast and dialog
  arguments, UI-named object properties). It also follows local helper returns,
  displayed parameters back to their call arguments, conditional values,
  render callbacks, reactive memos and constant vocabulary lookups. Exported
  prose helpers ending in `Sentence`, `Phrase`, `Label`, `Title` or `Words` are
  checked at their definition, including in `.ts` files. This remains a
  syntactic, single-file check: imported implementations, aliases, arbitrary
  mutations and unnamed external producers are not followed. Intentional
  literal boundaries may carry `{ site, reason }` entries in the baseline;
  `--update` preserves those reasons. It does not read inline script
  strings (the GH #572 unsupported-engine card stays English), and a converted
  site leaves the baseline only through `--update`.
- Separately, it fails a call of `t`, `render` or `renderEnglish` (a named
  import, or a member of a namespace import) that runs while the module loads:
  at module level, as an argument of a load-time call other than
  `createMemo`/`createEffect`/`createRenderEffect`/`createComputed`, in a
  function invoked or passed to a call at load, in a class static
  initializer, or in a static method or static getter of a class in the same
  file that is called (`Class.m()`, `Class["m"]()`, `this.m()` from a static
  context, or passed as an argument) or, for a getter, read at load. It is a
  syntactic, single-file check: aliases, instance-method calls and cross-file
  calls are not followed.
- Toasts take `Msg | RawText` (a bare string is a legacy site the ratchet
  counts). A toast shows in the active locale; its dedupe key, the session
  error list, Copy and the debug log use the message id and English text, so a
  report reads the same in every language. The persisted flight recorder keeps
  its fixed `error_toast` event and never receives text.

## Locale choice

- Device preference `ui_language` in `tine-settings.json` (`""` = system
  default), written through the existing app-string path. System default = the
  first of the system's languages that a shipped locale serves (exact tag, then
  language subtag), else English.
- Every webview awaits `startUiLanguage()` before it mounts (main, graph
  windows) or renders (Quick Capture). It settles once the chosen catalog is
  showing. Only the settings read is bounded (500 ms): a slower read shows the
  system's language and switches when the read lands, unless anything changed
  the language meanwhile. A read the IPC call rejects toasts and keeps the
  system's language. An unreadable or invalid `tine-settings.json` reads as
  absent, as for every device preference: the system's language, no toast.
- One operation owns the UI language at a time (`src/i18n/preference.ts`):
  the startup read and its fallback, a broadcast from another window, the
  user's choice and a failed save's re-read each start one, and only the
  latest may show a locale, fall back to English or report to native code.
  Concurrent loads of one catalog share a single load. Startup settles when the
  latest operation has, following each supersession: a broadcast during
  startup holds the mount until its catalog shows, and a catalog it made
  obsolete never does.
- The committed choice is `tine-settings.json` alone; the frontend keeps no
  copy of it. A failed save toasts and, unless something newer changed the
  language meanwhile, reads the file again and shows what it holds. The
  language does not use the generic device-preference write queue.
- The boot card (`index.html`, shown until the frontend mounts) reads its text
  from `ui_locale_resolved`: the main window's at launch
  (`__TINE_BOOT_TEXT__`; main starts hidden and is revealed after the first
  stable frame), a graph window's when that window is built
  (`__TINE_WINDOW_BOOT_TEXT__`), so a graph opened after a language change
  shows the language the frontend last reported. The card is best effort: a
  graph built in the moment between a change and its ordered report (for
  example, while that window's lane finishes an earlier command) shows the
  previous language until the frontend mounts. Graph windows are not hidden:
  an unmounted window always shows its boot card. Mobile shows it in English
  (DESIGN rev. 3).
- The frontend reports the resolved tag through `set_ui_locale` (an ordered
  write, `ORDERED_COMMANDS`), stored as `ui_locale_resolved`; the stored value
  and the tray relabel change under one lock, in call order. Native code never
  negotiates.
- A change applies live and is broadcast (`ui-language-changed`) to the other
  windows.

## Checks

| Check | Where |
| --- | --- |
| Catalog parses; no orphans, unknown references, cycles, unsupported functions; variable subset; shell literal-only; derivatives current | `src/i18n/i18n.test.ts` |
| Literal UI text sites only shrink, by identity (`src/i18n/literals-baseline.json`); no load-time resolution | `src/i18n/literals.test.ts`, `scripts/i18n-literals.mjs` |
| Command message ids follow the command ids, without collisions | `src/i18n/commands.test.ts` |
| Live switch, persistence, bounded startup read, late and failed reads | `src/components/LanguageSetting.test.tsx` |
| Localized toasts keep English reports | `src/components/Toasts.test.tsx` |
| Startup read, catalog loads, broadcasts, choices and failed saves resolve latest-first; only the latest reports to native | `src/i18n/preference.lifecycle.test.ts` |
| Shell text falls back to English | `src-tauri/src/i18n_shell.rs` tests |
